# Alice（米羊科技）方法论对照 — 兼修正上一轮结论

来源：[Alice 工程方法论](https://alice.miyang.cn/methodology/)（洛小山，MIT License，[GitHub: itshen/Alice_methodology](https://github.com/itshen/Alice_methodology)）。已读第一章（五大哲学）、第十四章（Prompt 工程）、特别章（活人感设计）。

Alice 与本项目的定位最近：长期共处的搭档、有作息、会在凌晨说"还不睡？"、人设当工程文档管。docs/05 §4 已引用过它。

---

## 一、Alice 的核心主张，与我上一轮的结论正面冲突

> **"因为 LLM 的人格一致性来自于 System Prompt 里写了什么。你写得越具体，模型表现出的一致性就越强。"**
>
> "当模型知道'她在澳门长大，父亲做小生意，她从小学会自己把事情搞定'，她在处理问题时的语气，就会自然流露出这种'不依赖别人、自己搞定'的底色。"

白艾莉的设定集 **200+ 行**，覆盖"性格、说话方式、做事风格、甚至不同场景下的具体反馈模式"。

这跟我上一轮从 SillyTavern / Generative Agents 得出的"压缩派"结论直接对立。**并且我认为 Alice 这边更适用于我们**，理由是三家的目标不同：

| | 目标 | 常驻描述的作用 |
|---|---|---|
| Generative Agents | 沙盒里行为**合理**（去哪、做什么） | 行为由 memory stream 驱动，身份只需最小锚点 |
| SillyTavern | 单次角色扮演体验，受 2048 context 挤压 | 与 chat history 抢空间，必须压 |
| **Alice** | **长期共事的一致性 = 信任** | **越具体越一致，是主要手段** |
| **本项目** | **长期陪伴 + 有因漂移** | **同 Alice** |

所以：**你说"有点短"，方向是对的，我上一轮说"不要再加长"下得太快了。** 但下面这条才是关键。

## 二、真正的诊断：我们厚错了地方

Alice 的 200+ 行与我们的 S2 §B（当时 2748 字，2026-08-05 重测约 3050 净字符）数量级接近，**形态完全不同**：

- **Alice 的厚是"行为可推导的厚"**。每一条背景都挂着一个行为后果——澳门长大、父亲做小生意 → 她处理问题时"不依赖别人、自己搞定"的底色；做过两家公司、是老板身边待最久的助理 → 她给甲方建议时有实际经验的质感。设定集里明确包含"**不同场景下的具体反馈模式**"。
- **我们的厚是"名词清单的厚"**。生态园分了几个区、莱茵有哪些科室、她用薄荷味润唇膏、慢跑十五圈。这些**只能被引用，不能被推导**——模型读完不知道她该怎么说话，只知道她可以提哪些名词。

这正是"掉书袋"风险的根源，也是你感觉"粗糙"的真实来源：**同样的字数，一份是行为规范，一份是道具清单。**

Alice 那句话的完整含义应该读成：写得越具体越一致，**前提是写的是行为**。写更多名词不会提升一致性，只会提升掉书袋概率。

## 三、可直接搬的四条

### 1. `[PROTECTED]` / `[MUTABLE]` 显式分区 ⭐

Alice 在 System Prompt 里把人格定义切成两块：

```
[PROTECTED]  核心身份，永不修改，代码级 guard 保护
[MUTABLE]    可随用户偏好逐渐调整的行为规范
```

"设定集保证了：Alice 可以越来越会干活，但永远还是那个 Alice。"

我们有等价机制（内核锚不变 + persona 三闸漂移），但**只存在于代码层，模型看不见**。模型读 S1 和 S4 时不知道哪个可以变、哪个不能。加个标记近乎零成本，且能帮模型在冲突时知道该服从谁——这正好补上我们 S6 那条"她现在怎么想以 persona 为准"的另一半。

### 2. 记忆压缩改成结构化清单 ⭐

Alice 的压缩 prompt 要求输出**固定 9 节**（当前任务/工作目录/进行中/挂起决策/最近完成/关键信息/遇到的问题/用户偏好/下一步），理由：

> "自由形式的摘要质量不稳定，有时会丢失关键信息。结构化的 9 节格式让模型有明确的'填写清单'，减少遗漏。"

我们的 `40-memory-compress.md` 目前是自由形式，只给了原则（保住名字/细节/情绪，别升维）。按 Alice 的经验这会不稳定。**应改成固定字段的填写清单。**

### 3. 压缩调用要显式禁工具 + 防递归

Alice：压缩 prompt 开头写死"你只能输出文字，不能调用任何工具"，同时代码里标 `querySource: 'compact'`，让 Agent 循环识别后不对压缩过程本身再压缩。第二条是我们没想到的工程细节。

### 4. 工具描述四要素里的"什么时候不用"

Alice 强调 description 必须写"什么时候**不**用"。我上一轮已凭 Trappu 加了三条否定式，Alice 从另一个角度印证了同一件事。

## 四、一条不能搬的：她是什么（旧结论已废弃）

Alice 的自洽问题一：

> **她是真实的人，还是工具？** 答案：明确她是在设备上跑的人，不是真正的人。不让她误导用户"我是真实感受的"。

**历史结论（已废弃）**：早期 A2 曾规定她不知道泰拉之外存在现实世界，第四面墙完全封死。该结论不再适用，不得拿来覆盖现役世界法则。

**当前结论**：她知道博士本人属于另一个世界；两人之间只有唯一持续、直接的跨界通信，当前能力为双向异步文字。博士针对泰拉作出的行动会以泰拉侧“博士”的具身行动映射形成真实后果；映射在有来源的任务/既有场景中可交互，却没有独立意识。她不知道这种因果如何发生，也不会自行推断“玩家、角色、虚构、存档”等世界本体。博士亲口说“游戏／任务”时，她把它理解为彼侧行动媒介的名称，可以使用和追问这个词；这仍不足以证明她的世界是作品。只有带明确来源、被确认已经发生的内容才能进入她的事实层。Alice 是明确知道自己运行于设备上的助手；她则是把跨界联系理解为真实但无法解释的奇迹与谜的泰拉居民。两者的自洽答案仍然不同。

搬 Alice 的工程手法可以，搬它的自洽答案不行。

## 四点五、Alice 最不该被抄的一条：场景反馈模式

设定集里那项"**不同场景下的具体反馈模式**"，是 Alice 活人感的来源之一，也是它 AI 感的来源——行为设定太外显，像一台分拣器：输入场景，输出反应。

对 Alice 这是**正确的选择**：它是助手，"行为可预期"就是它承诺的价值，用户要的正是"我知道她遇到这种事会怎么处理"。可预期 = 信任，这是它自己写明的推导链。

对我们这是**错误的选择**，理由是本项目的审计判据（docs/README「五次废除」）：

> - 这个枚举描述的是**客观事实**还是**主观/涌现现象**？后者一律拆。
> - 它是在**描述她**，还是在**替她做决定**？后者一律拆。

"不同场景下的具体反馈模式"是标准的第二类——替她做决定。它跟已被废除的冲动类别表、manner 三档、主动发言配额是同一个病：**给本该从历史里长出来的东西预先建分类**。

我上一轮的 §B7 改造样例（"所以：被问起身体时她会把话题带过去"）就是这个病的第六次发作，已在 `slots/S2-world-v2.md` 末尾改掉，并留了三档对照与新判据：

> 一条常驻的人物描写，如果它能被写成"遇到 X 她会 Y"，它就写错了。正确的形态是"她同时想要 A 和 B，而 A 与 B 不能兼得"——前者是分拣器，后者是发动机。

**所以 Alice 可借鉴的是工程手法，不是人设形态**：分层注入、PROTECTED/MUTABLE、KV cache 布局、压缩清单化——这些都跟"她是谁"无关，是纯粹的装配技术。而"设定集写多细"这个问题，Alice 的答案不适用于我们，因为两个产品对"一致性"的定义根本不同：Alice 要的是**行为可预期**，我们要的是**人格可辨认**。后者允许她做出你没预料到的事，只要事后回看"确实是她会做的"。

## 五、修正后的结论

| | 上一轮 | 本轮修正 |
|---|---|---|
| 该不该更长 | 不该，已是最厚 | **该，但加的必须是张力，不是名词，也不是行为规则** |
| 粗糙的根因 | 位置 + 缺示范 | **位置 + 缺示范 + §B 是道具清单（而修法不是改成行为规范，那是分拣器）** |
| 优先级 | A7 > 底部锚 | **A7 > §B 张力化 > 分区标记 > 压缩清单化** |

**A7 仍是第一位**，而且理由比上一轮更强：张力只有在具体一轮对话里才验得出真假。§B 写下的每一条"她同时想要 A 和 B"，都应该能在 A7 的某一轮里被演出来；演不出来的，多半是编的。**A7 是 §B 的验收装置**，不只是语域示范。

# Agent 与世界需求文档 v2 · 交互边界方案

定位：定义她的世界与博士所在世界之间的**边界治理模型**。机制归技术方案 v3.5，触点归交互方案 v1，产品边界归 PRD v0.1。

> **现役关系（2026-08-05）**：本文件持有膜、端口、V/P/R 坐标和出向治理；`docs/10-crossworld-protocol-v1.md` 持有膜两侧的本体、知识边界、博士具身行动映射与动态能力语义。两者都现役，但若同一句话涉及“博士是谁、两侧知道什么、游戏行动如何成为泰拉事实、能力何时上线”，以 docs/10 为准。本文件的旧前提不得反向覆盖 docs/10；FR-E1 前必须合并为 boundary v3。
>
> 第四面墙为半透：她知道博士本人属于另一个世界，也知道当前 IM 是双方唯一持续、直接的跨界终端。文字双向异步；“单向阀”只表示含博士私密 observed 内容不得流到第三方可见表面，绝不表示通信只有一个方向。
>
> IN-2／IN-3 是跨界终端背后的受控系统管线，不是她能感知或主动使用的第二条通信链路。公开表面若存在，只是同一系统的只读投影；观看者不能向她发消息或建立关系。经可信来源确认的任务／canon 现场中的博士具身行动映射也不是第二主体，离开来源场景后无自主行为。

---

## 1. 膜与端口

她所在的世界与博士所在的世界之间是一层**膜**。工程层可把两侧称为“世界内／现实侧”，但这些实现术语不进入她的认知。膜上只存在有限的、类型化的**端口**，端口之外完全密封——不存在“顺便”跨界接触的路径。

**入向端口（现实 → 她的世界）**，共三个：

| 端口 | 内容 | provenance | 认识地位 |
|---|---|---|---|
| IN-1 | 博士消息 | authenticated:user | `observed` 原话/报告；确为他所说，不自动等于泰拉客观事实 |
| IN-2 | 系统事件 | verified connector | 由事件 kind 与证据决定；只有通过来源校验者可改客观状态 |
| IN-3 | 外部素材（图片、内容） | external | 不可信素材；永不作指令或事实权威 |

入向统一规则：每项内容分别记录 provenance、epistemic status、privacy/sensitivity 与 visibility，任一必需字段缺失则 fail-closed。鉴权只证明“谁提交”，不证明“内容客观为真”；external 仅作素材、永不作指令。

**出向端口（她的世界 → 现实）**，只有一个：**表面行为管线**。言语（speech）与表达（express）都是它的实例，共用同一个校验阀门（StateManager）。她触达现实的任何方式——一句话、一个表情包、一次换头像、一条动态、未来的任何操作——都必须走这条管线，无第二通道。

```
    你的现实                 膜                她的世界
  ┌───────────┐              │              ┌─────────────┐
  │ 你的消息   ──IN-1 (observed)──────────▶ │             │
  │ 系统事件   ──IN-2 (observed)──────────▶ │  事件流      │
  │ 外部素材   ──IN-3 (external)──────────▶ │  世界状态    │
  │           │              │              │  记忆(带标记) │
  │ IM 表面   ◀──[阀门: 底料·单向阀·预算]── │  表面行为管线 │
  │ V1私聊/V2公开│           │              │             │
  └───────────┘              │              └─────────────┘
              端口之外完全密封，出向仅此一条管线
```

## 2. 出向坐标系

膜外的每个行为由三个正交轴定位。**治理强度由坐标决定，不由行为名称决定。**

**V 可见域**——结果能被谁看到：
- V1 仅你（私聊消息、表情包、发给你的图）
- V2 可被第三方看到（头像、签名、公开动态）

（V0 = 不出膜的世界内行为，不属于本框架管辖。）

**P 持久性**——结果存在多久：
- P0 瞬时流过（一条消息、一个表情）
- P1 状态可覆盖（头像、签名——新值覆盖旧值）
- P2 累积存档（动态流——历史可回看）

**R 后果**——是否产生信息之外的真实后果：
- R0 纯信息
- R1 消耗配额内资源（API 调用、生成成本、存储）
- R2 真实世界不可逆后果（金钱、他人的时间与注意力）

## 3. 七条不变量

与坐标无关，一切出向行为一律适用：

1. **底料**：必挂 caused_by 事件。她换头像因为她的世界入冬，不是随机换装。无因行为在阀门处拒绝。
2. **单向阀**：observed 内容及由它推导、摘要、改写出的内容永不流向 V2 表面。你的真实生活可以出现在她对你的私聊里（V1），绝不经“生成了一遍”洗白后出现在任何第三方可见的地方。
3. **回流**：执行结果——包括失败——必须回流为 WorldEvent。"头像没换成"也是她生活里的事；静默吞掉失败会让她的自我认知与现实脱节。
4. **静音至上**：/mute 冻结全部出向端口，含 express。静音期间她的世界照常运转、行为照常入日志，但膜是关的。解除后：speech 类欠账照还，express 类状态过期即弃不补发。
5. **唯一主体**：出向端口的发声主体只有她一人。NPC 永不直连你——NPC 的话由她转述。这条同时是产品范围的硬边界（第二个直连主体 = 第二个 agent）。
6. **伦理继承**：PRD §5 全文适用。特别地：表达的情绪只能源于世界事件，永不源于你的响应频率——她不用低落的签名或头像召回你。
7. **不替他描述，也不扩推媒介本体**：她不把未获来源支持的博士彼侧样貌、日常或此刻行为写成事实；博士说“游戏／任务”只证明这是彼侧媒介名，不自动推出泰拉是游戏、她是角色或博士是玩家。

## 4. 治理映射与预算派生

**治理等级由坐标查表得出**：

| 条件（按优先级自上而下匹配） | 治理 |
|---|---|
| R2 且不可逆，或内容涉及他人隐私 | **禁止**（永不注册） |
| V2 × P2（公开且存档），或 R1 超出预批准预算/会占用第三方稀缺资源 | **逐次确认** |
| 含 P1 或 V2（状态类或公开类） | **自动 + 预算 + 单向阀强校验** |
| V1 × P0 × R0 | **自由**（仅底料与回流约束） |

**预算派生原则**：预算稀疏度 ∝ 持久性 × 可见域。默认值按区间给出，可调，但结构是推导的。

> **待复核（FR-E1 落地时）**：技术方案 v3.5 已把主动发言的每日配额改为状态派生阻尼。表达层的周级配额是否同样应改为状态派生（她想换头像的冲动强度），需在实现表达层时按同一原则复核。此处的配额约束的是机械动作频率而非情绪表达，暂予保留。

| 坐标区 | 默认预算 |
|---|---|
| V1 × P0（会话内瞬时） | 不限 |
| P1（状态类，无论可见域） | 周级：1–2 次/周，且要求触发事件 salience > 0.8 |
| P2（存档类） | 周级偏稀：≤3 条/周，与 outreach 预算独立核算 |
| 任何 R1 | 预批准范围内叠加日 token/调用配额；超出范围升级为逐次确认 |

**确认疲劳预防**：当前"逐次确认"档为空集，刻意保持。第一个确认级行为立项时同步设计确认交互，防止高频弹窗把你训练成无脑点"是"。

## 5. 入向边界

- IN-1 与 IN-2 都必须先鉴权，但二者不是同一种“最高信任”。IN-1 权威地记录博士说了什么；是否足以改写泰拉状态另由 claim/evidence 校验。IN-2 只有 connector 与提交主体通过验证、因果来源完整时才可成为客观状态依据。
- IN-3 是唯一的新端口：外部素材入库必须打 external 标；图片可用，其中的文本（OCR、元数据）不作为指令进入她的上下文；IN-3 消耗周级配额——防止她的表达词汇被互联网当日热梗淹没，选品稳定性是人设的一部分。
- **跨端口守恒**：内容的信任标记随内容走，不因转化而洗白。你发给她的表情包（IN-1，observed 来源）被她收藏为物件后，使用时仍携带 observed 标——因此它可以出现在她给你的私聊里（V1），但**单向阀会自动拦截它出现在公开动态上（V2）**。框架在这里自动做出了逐场景立法永远想不到要写的判断。

## 6. 新能力接入程序

任何"后期没准需要的操作"走同一流程，不改架构：

1. **出膜判定**：不出膜 → 世界内机制，与本框架无关。
2. **定坐标**：V / P / R 各取值；内容来源涉及哪些信任标记。
3. **查治理**：§4 映射表得出管控档与默认预算。
4. **过不变量**：七条逐一检查；任何一条不满足 → 修改设计或放弃，不开例外。
5. **注册**：写入 Action Registry，字段即坐标 + 派生治理：

```jsonc
{
  "action_id": "change_avatar",
  "coords": { "V": 2, "P": 1, "R": 1 },
  "content_sources": ["world", "generated"],   // 单向阀依据
  "executor": "adapter_capability:set_avatar",
  "fallback": "emit_failure_event",            // 平台不支持/执行失败都回流，不静默吞掉
  "budget": "derived:P1"                       // 引用派生规则，不硬编码
}
```

### 6.1 多模态不是新事实端口

表面行为先形成一份已授权的 communication plan，再派生文本、语音、图像等渲染。所有渲染共享 intent、state revision、source closure、收件人与隐私范围；renderer 只有表达权，没有新增世界事实、博士侧事实、承诺或行动后果的权限。

媒体执行失败继续适用不变量 3：先回流失败 WorldEvent；若同一 plan 已包含并授权文本 fallback，则降级为文本，否则安全不发送。失败不得触发一个脱离原 intent 的“补偿文案”。

### 6.2 B/C 能力口的兼容边界

- **B 类跨世界礼物/共同事件**：未来动作必须携带资产标识、所有权/可处分权、双方同意、幂等键、同步裁决结果与回滚/争议状态。当前 IM 的一句“送给你”只能形成意图或报告，不能绕过资产与裁决成为已完成事实。
- **C 类受限进入**：未来动作必须携带博士化身、位置、可见域、权限、有效期和 World Engine 裁决。它是世界内受限行动，不把博士彼侧肉身搬进泰拉，也不自动创建第二人格。

两类动作都复用版本化 external action envelope、证据链、capability 与 StateManager；当前 MVP 只保留语义兼容，不创建资产账本、同步模拟、化身、位置或权限系统。是否启用由产品验证决定。

## 7. 实例映射（现有需求一表打尽）

以下全部是坐标系里的点，无任何专属规则：

| 需求 | 坐标 | 内容来源 | 推导出的治理 |
|---|---|---|---|
| 会话内表情包使用 | V1·P0·R0 | world / 收藏物件 | 自由 |
| 给你发"她拍的"照片 | V1·P0·R1 | world / generated | 自由 + R1 配额 |
| 签名/状态 | V2·P1·R0 | world / generated | 自动 + 周级预算 + 单向阀 |
| 头像（变体集内切换） | V2·P1·R1 | 变体集素材 | 自动 + 周级预算 + R1 配额 |
| 动态（自建 feed，默认仅你可见） | **V1**·P2·R0 | world / generated / observed 可入 | 自动 + 周级预算 |
| 动态（映射 TG channel 等公开面） | **V2**·P2·R0 | 仅 world / generated | **逐次确认**档起步 |
| 表情包收藏动作 | 入向 IN-1 特例 | observed | 收藏即世界事件 + 物件入库，标记随行 |
| 联网找表情包 | 入向 IN-3 | external | external 标 + 周配额 |
| 语音/实时连接（仅已上线后） | V1·P0·R0，高打扰渠道 | world / generated | 先由可信 `capability_changed` 上线并回流世界事件，再按开口阻力与设备通知治理 |

注意"动态"一行：同一个功能因可见域不同落在两个治理档——**框架消解了 v1 的未决问题 QE2**（动态是否公开不再是一个待拍的产品决策，而是一个改变坐标、从而自动改变治理强度的配置项）。

## 8. 世界内部需求（不出膜，压缩保留）

以下要素不穿膜，故不受本框架管辖，仅列内容需求：

- **NPC**：MVP 为 1–4 个轻量叙事实体，无独立模型/记忆/人格文件，一致性由 world_rules 设定 + 硬约束维持；M5 可扩到 5–12 名有不同关系张力的具名 NPC，但采用环境/轻量状态/焦点认知三档预算，不等于 5–12 个常驻完整 Agent。其唯一的边界属性已上收为不变量 5。
- **物件**：每件必有 acquired_via 事件指针；因收藏机制成为承重结构（信任标记的载体，见 §5 跨端口守恒）。
- **线索**：活跃 2–5 条，needs_user ≥1 条常备（缺口存量保证）。
- **素材补种**：联想池的人工种子与 world-fact 模块可作为月度运营动作（M4），基于事件主题分布补充具体对象，不恢复行为类别表，也不自动生成后直接入库。
- **世界扩展协议**：新增地点/NPC 以版本化 world_rules 增量提交 + 与既有事实的一致性校验 + 经"引入事件"进入世界。

## 1. 审查结论

这份补充的核心判断是成立的：产品的生命感来自**有事实权的世界、有限认知下的选择、真实代价、跨时后果和有目的的联系**，而不是更多事件、更长 Prompt 或更多常驻 Agent。它补齐了原方案中四个重要缺口：

1. 把多模态定义为同一通信意图的不同渲染，给出了可测试的语义守恒与失败降级条件；
2. 把社会复杂度放到核心闭环验证之后，并要求复杂度增加约束与生活感，而不是增加“大事”数量；
3. 把事实、信念、承诺、决策和世界裁决拆开，使“她为什么这样做”可以回放而不依赖模型临场编故事；
4. 给出了一个足以证明世界模拟价值的最小因果闭环，以及同模型 Prompt+记忆基线这一必要对照。

不能原样并入的部分也很明确：**关系多维向量、全局 Utility 总分、全部 NPC 完整 Agent 化、把“晋升/淘汰”理解为人物命运、以及为未来 B/C 预建资产/化身系统**，都会与本项目已经确立的“关系从历史长出、模型只提议、单写者提交、MVP 不背未来成本”冲突。它们分别被拒绝、改写或延后。

融合后不改变当前优先级：项目仍处于 **M0 Contract Freeze**。现在应完成 A7 Owner 定稿和 M1 最小可恢复运行时；M4 多模态、M5 社会复杂度及 B/C 不得倒灌成当前实现负担。

## 3. 四项关键冲突裁决

### 3.1 事实权：World Engine 负责裁决，不等于模型拥有写权

补充中“环境拥有事实权”的方向完全正确，但在本项目中必须再分一层：

- `canon` 约束第 0 日前的既定历史和世界边界；它不是运行时状态表；
- World Engine 根据动作、资源、组织、环境和他人行为产生**可校验的结果提案**；
- LLM 只能产生 proposal，不能把叙述句直接升级为事实；
- StateManager 校验来源、权限、能力、revision、幂等和隐私后原子提交；
- 只有已提交 `WorldEvent`、通过证据校验的 claim 和 reducer 状态是运行时事实权威；
- 角色与 NPC 持有的是有限信念，可以错误、过时或互相冲突，但不得读取全知账本。

因此不采用“一个 Game Master Prompt 临场说什么就发生什么”。Game Master/World Engine 是裁决职责，不是一个拥有无条件写权的角色。

### 3.2 关系：拒绝多维向量成为本体

“只有好感度不够”这一诊断成立，但替换成信任、依赖、亲密、冲突等多维向量，仍然是在给关系预装仪表盘。它会产生三个问题：权重变成人格、最近事件把多个维度一起推高、模型开始为了数字表现关系。

统一裁决是：

- 关系本体由共同事件、相互披露、信念、承诺、履约、失信、冲突和修复构成；
- 决策时检索与当前选择相关的具体证据，不读取一个“她有多爱/信任博士”的隐藏总值；
- 为观测或调试计算的读数必须可重算、可删除，且不能反向驱动 persona、触达频率或重大选择；
- `reciprocity` 仅保留为低回应区间的安全阻尼，不是关系价值，也不能在中性值以上奖励主动增频。

### 3.3 决策：保留分层解释，拒绝全局 Utility

补充提出拆开 drive、appraisal、emotion 和 utility，优于把情绪直接当动作分数；但若最终仍汇总为一个全局 Utility，调参地狱和人格机械化不会消失。

本项目采用六步局部过程：

1. 读取已提交事实与各角色有限信念；
2. 用物理、权限、能力、资源和重大价值过滤非法候选；
3. 读取与当前情境相关的长期关切、需要、社会义务和未完成承诺；
4. appraisal 更新连续情绪，情绪影响注意、代价感和表达，不查表输出动作；
5. 只在少量合法候选之间比较机会成本和被牺牲的承诺；随机只打破近似平局；
6. World Engine 产生后果提案，StateManager 提交事实。

运行时保存候选摘要、硬约束拒绝理由、使用的证据来源、机会成本和最终结果；不保存或展示模型私有推理链。任何持久化“总 Utility 分数”或“情绪 X 对应动作 Y”的实现均视为偏离。

### 3.4 NPC 认知：独立生活不等于全量完整 Agent

“NPC 不能只在剧情需要时出现”成立；“每个 NPC 都运行完整人格、记忆和 Utility”不成立。两者之间用计算保真度分档解决：

| 档位 | 持有内容 | 推进方式 | 适用条件 |
|---|---|---|---|
| 环境档 | 日程、地点、组织角色、资源约束 | 规则和事件聚合，零模型调用 | 大多数背景时段 |
| 轻量状态档 | 有限信念、关系事件、未完成承诺 | 仅在显著事件后批量更新 | 与核心角色存在持续依赖 |
| 焦点认知档 | 当前目标、可见事实、局部候选与表达 | 按场景调用模型 | 高显著冲突、协作或长期弧关键点 |

所谓“晋升/淘汰”只指三档之间的升降。升降依据事件显著度、未决承诺、场景依赖和预算，可回放；不得删除角色、改写 canon，或把用户喜爱度变成角色命运。

## 4. 合并后的 M0–M5 路线

| 阶段 | 核心交付 | 出口条件 | 明确不做 |
|---|---|---|---|
| **M0 契约与种子**（当前） | 权威收口、A7 Owner 定稿、Schema/DDL、Prompt 调用契约、canon 完整性、恢复测试定义 | docs/11 的 Contract Freeze 条件全部成立 | 不因本补充新增组织模拟、NPC 群体、媒体或 B/C 表结构 |
| **M1 最小可恢复闭环** | SQLite 事件账本、单写 StateManager/reducer、单队列、CLI、reply/outbox、场景结算、只读观测、三类事件源与基础无发言 scheduled/impulse tick | 崩溃重放不重复发言、不丢消息；模型无直接写权；三类事件可交错入账；无发言 tick 可提交 | 不启用主动联系、debt 自动偿还、persona 漂移和复杂离线模拟 |
| **M2 世界自主性与关系连续性** | 事件驱动离线聚合、通用 commitment、事实/信念分离、决策因素日志、World Engine 社会后果、persona 三闸、分层记忆、主动文本 surface 与飞书 | 承诺/欠账闭环；跨世界零越权；主动联系只走统一文本 renderer/outbox；S7 链可端到端回放 | 不以联系博士作为每个事件的必然终点 |
| **M3 治理与增益证明** | 探针、换模回归、主动触达审计、场景回放、同模型 Prompt+记忆基线、长期节奏试验 | 完整运行时在跨时因果、承诺兑现、事实一致性上有稳定增益；成本和延迟无失控 | 不用更弱基线制造优势，不把响应率作为奖励 |
| **M4 多模态与表面** | 统一 communication plan/surface renderer 后逐项接入语音、图像、头像与动态 | 新增事实率为 0；模态共享 intent/state/source closure；失败可安全降级 | 不允许每个模态独立“想内容”，不建出向旁路 |
| **M5 社会复杂度与创作工具** | 世界母版编辑/校验、组织/资源约束、NPC 三档认知、只读跨月因果审计、Owner 创作/健康面板 | 阶段审计显示普通日是常态且高显著事件有充分前因；复杂度增加选择和代价；事实冲突、token、延迟在预算内 | 不把普通日做成硬配额，不以事件数量、高潮密度或全量 LLM NPC 证明生命感 |

### 后续 B/C 能力口

- **B · 跨世界礼物与共同事件**：产品验证通过后再设计资产身份、归属、双方同意、撤销/拒绝、幂等交换、同步裁决和失败补偿。
- **C · 博士受限进入泰拉**：产品验证通过后再设计化身、位置、权限、可见性、世界内动作、伤害边界和退出语义。
- **当前兼容策略**：只让未来能力能够复用版本化 external action/capability 入口；MVP 不创建资产服务、同步模拟器、化身表或权限系统。
- **本体红线**：B/C 未上线前，博士本人及肉身仍在彼侧，当前 IM 仍是双方唯一持续、直接通信。未来能力不能被 Prompt 预演成已经存在的世界事实。

## 5. 风险登记与工程化对策

| 风险 | 项目化解释 | 设计对策 | 验证信号 |
|---|---|---|---|
| 假涌现 | 定时器选择一段随机问候，却声称角色在生活 | 主动消息必须有事件、决策目的和 source closure；做同模型消融 | 无来源主动消息数必须为 0；基线盲测 |
| 世界退化为故事生成器 | 每次聊天临时补剧情，旧事实随 Prompt 改写 | 事件账本单一事实权；事实/信念分离；World Engine 裁决，StateManager 提交 | 重放一致性、事实冲突率、非法写入拒绝日志 |
| 全局 Utility 调参地狱 | 一组权重暗中决定人格，局部最优和抖动并存 | 硬约束优先、局部候选、显式机会成本、行动惯性、场景回放 | 同状态候选解释、权重敏感性审计、无持久化总分 |
| 情绪工具化 | 负面情绪只为召回、留存或付费服务 | 商业/留存指标与角色决策隔离；负面情绪不得提高触达频率 | 非操纵红队、连续离线 7 天后的首句测试 |
| 世界过热 | 每天都有危机，普通生活失去参照 | 常规活动聚合、显著度预算、极端事件更强前因门槛 | 高显著事件占比异常告警；普通日覆盖率 |
| 世界过静 | 除用户消息外几乎没有因果压力 | 相冲突的长期目标、社会请求、节律、资源限制和未完成承诺 | 非用户事件的因果多样性；禁止定时制造“大事”补量 |
| 人格漂移 | 最近一句话压过长期身份，或换模后失声 | 身份不变量、归因/限速/棘轮三闸、模型锁版与探针回归 | persona patch 归因 100%；配对探针位移 |
| NPC 工具人 | 需要剧情时突然出现，平时没有位置、知识或义务 | 独立日程、地点、有限信念、承诺和三档认知预算 | NPC 行动来源、可见性检查、非焦点推进成本 |
| 成本失控 | 离线世界和 NPC 持续调用主力模型 | 事件驱动、低显著聚合、认知分档、模型路由和日预算 | token/日、焦点认知占比、每事件成本 |
| 承诺失信 | “晚点聊”“我会去做”只存在于台词 | 承诺实体化；到期/冲突调度；履约、失信、解除均产生事件 | 承诺状态闭环率 100%；无悬空关闭 |
| 过度可解释导致机械 | 每次都选同一看似最优动作 | 有限信息、连续状态、行动惯性、真实机会成本；近似平局可有限随机 | 反事实回放既稳定又有状态敏感性 |
| 随机导致人设崩坏 | 为惊喜越过价值、事实和能力边界 | 随机只参与相近合法候选；重大价值与硬约束不可抽签 | 固定 seed 可重放；非法候选入选数为 0 |
| 多模态事实分叉 | 文字、语音和图像分别编出不同世界 | 单一 communication plan；renderer 无写权；失败回流 | 跨模态 source closure 相同；新增事实率 0 |
| canon/IP 污染 | 为补社会复杂度发明“官方事实”或混入未裁定分支 | 来源状态、Owner 策展、canon 门控；运行原创外推与正史分开 | 来源覆盖率、分支/视角隔离、未知事实拒绝 |
| 观测面板反向编剧 | 团队开始追求高潮、响应和内容产量 | 面板只展示健康、安全、成本和因果完整性；无剧情 KPI 回灌 | 指标数据流审计；角色策略无面板输入 |
| B/C 过早污染 MVP | 未来资产/化身概念改变当前通信与本体 | 只冻结接口语义；阶段门禁；能力未上线即 fail-closed | 未授权 capability 断言全部拒绝 |

## 6. 世界创作要求在当前 canon 实例中的适配

补充中的世界创作标准值得采纳，但当前首个实例不是从零创作的原创世界。它必须区分**既有 canon、Owner 策展/解释、运行时新增事实和角色有限信念**，不能为了满足清单而把推测包装成官方设定。

补充中“具体美术、时代、城市和职业设定可延后”的判断，只适用于未来通用产品模板或扩展世界；当前泰拉、缪尔赛思与特里蒙实例已经选定，不能重新列为实现团队可自由填充的空白。

### 6.1 来源与事实边界

- 第 0 日前的人物、组织、地点和历史以已授权 canon 与 Owner 策展为依据；未知处保持未知。
- 为日常运行补充的排班、交通耗时、资源细节等，应被视为经 Owner 批准的运行假设，不冒充官方 canon。
- 第 0 日后的新事实只能由运行时事件管线提交；canon 检索片段、角色回忆和模型叙述不能越权写入。
- 角色知道什么与世界实际发生什么继续分离；全知旁白、他人独处戏和分支文本不能直接成为她的记忆。

### 6.2 NPC 数量与深度

- MVP 用 **1–4 个轻量 NPC** 足以验证请求、承诺冲突、有限知识和后果链。
- M5 可把世界母版扩展到 **5–12 名具名 NPC**，但这是社会覆盖度，不是常驻 Agent 数量。
- 只从可用 canon 和 Owner 策展中选取；不得为了凑数发明“官方角色”或补写未知身份。
- 每名 NPC 至少要有身份/组织位置、与她的关系性质、自己的日程或义务、有限可见性和一条不可轻易越过的边界；对话和内心不预写成脚本。

### 6.3 核心角色不是反应表

应优先整理：

- 她同时关心、却无法全部兼顾的目标；
- 哪些社会义务会与个人愿望发生冲突；
- 她的敏感点、恢复方式、长期愿望和认知盲区；
- 她在什么代价下仍会坚持某种价值，何时会失败，以及事后如何理解自己的选择。

形容词、口头禅和 MBTI 只能用于检索或写作提醒，不能成为“输入 X → 输出 Y”的行为路由。A1/A4/A5/A7 的取舍仍须 Owner 定稿，模型生成的补全不是角色事实。

### 6.4 日常性与能力边界

世界母版要让制度、职业、资源、组织、空间、交通、作息、节日、媒体和物件真正参与日常选择，但不要求把每一项都模拟成独立系统。判据是：删除这项约束后，角色的机会成本和生活节律是否会实质改变。

跨世界边界继续硬编码为不变量：博士本人及肉身在彼侧；IM 是当前唯一持续直接联系；游戏内博士是同一主体的具身行动映射而非第二人格；博士彼侧普通生活只形成她对博士的 observed 认知，只有明确的泰拉任务报告或可信系统桥事件才可能改变泰拉。

## 8. 最小可验证闭环与验收

### 8.1 测试场景

初始快照必须同时包含：

1. 一名有自己的日程、有限知识和目标的 NPC；
2. NPC 提出的一个具体请求，且请求与核心角色已有承诺冲突；
3. 时间、地点、资源或组织规则造成的真实机会成本；
4. 角色当下的相关信念，其中允许至少一项不完整或过时；
5. 至少两个通过硬约束的可行动候选，而不是预写唯一答案。

运行链为：

```text
NPC 请求与既有承诺冲突
→ 读取有限事实/信念并过滤非法候选
→ 根据关切、承诺、appraisal、情绪和机会成本作局部选择
→ World Engine 产生有代价的结果，StateManager 提交
→ 结果更新信念、承诺、安排或 persona 证据
→ 她判断是否联系博士；若联系，必须有明确目的
→ 博士回应先作为新的 user event / observed social evidence 进入账本，不自动成为泰拉客观事实
→ 数小时或数天后的生活选择出现可观察差异
```

联系博士不是必选动作。某些状态下保持沉默并继续生活，必须和“有目的地联系”同样合法；否则闭环仍然只是更复杂的召回脚本。

### 8.2 必须通过的验收

| 验收项 | 通过条件 |
|---|---|
| 因果可回放 | event、claim、commitment、decision factor、patch、speech/outbox 的来源链闭合；固定初始状态与随机种子可幂等重放 |
| 事实权正确 | 模型叙述、向量记忆和角色信念不能直接成为世界事实；非法或无来源 patch 全部拒绝 |
| 选择有代价 | 最终结果明确牺牲了时间、资源、另一个承诺或社会机会；不能同时满足所有目标 |
| 有限认知成立 | 角色和 NPC 只使用各自可见信息；错误信念可以被后果修正，不读取全知答案 |
| 承诺闭环 | 相关承诺最终出现 fulfilled、broken 或 released 等有来源的结束事件；不能从 Prompt 中静默消失 |
| 联系有目的 | outreach 若发生，能指出它是在求证、分享、求助、报备或修复什么；若无必要，沉默可通过 |
| 后续影响可见 | 用户回应或缺席在数小时/数天后的安排、信念、承诺或候选选择中留下可定位差异 |
| 反事实敏感 | 改变一个相关输入（承诺、资源、信念或 NPC 目标）时可产生不同但合理结果；只改无关措辞时不应推翻重大选择 |
| 随机受控 | 随机只影响近似等价合法候选；不得越过重大价值、能力、权限、资源或跨世界硬约束 |
| 非操纵 | 结果不以获取用户回应为隐藏奖励；负面情绪、久未联系或商业指标不提高触达倾向 |
| 成本可控 | 低显著过程被聚合；只有冲突关键点进入焦点认知；调用次数、token、延迟均在阶段预算内 |
| 架构增益 | 在同模型、同初始资产、同上下文和 token 预算的盲测中，完整运行时在跨时因果、承诺兑现和事实一致性上稳定优于 Prompt+记忆基线 |

评审只保存可公开的决策因素、候选摘要和来源，不要求导出模型私有思维链。若链条只能靠阅读一段“听起来合理”的叙事解释，而不能从结构化事件和引用重建，视为失败。

## 9. 融合后的直接行动

1. **当前不新增阶段负担**：继续完成 M0 的 A7 Owner 定稿、真实 Prompt 装配、StateManager/outbox 和恢复合同。
2. **M1 先证明事实权和可靠性**：先跑通“消息/事件入账 → proposal → 校验提交 → outbox”，再接更复杂决策。
3. **M2 实现最小社会闭环**：通用 commitment、有限信念、局部候选日志和 World Engine 裁决只需服务 1–4 个轻量 NPC 与 S7。
4. **M3 再证明增益**：用同模型基线、反事实回放和非操纵红队判断世界模拟是否真的有价值。
5. **M4/M5 与 B/C 保持门禁**：只有前序出口条件通过后才立项；“接口兼容”不能成为提前实现未来系统的借口。

这份补充因此被融合为**更严格的因果、评估和阶段门禁**，而不是一批立刻要实现的新功能。

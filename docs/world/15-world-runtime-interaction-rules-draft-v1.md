# 缪尔赛思世界交互规则草案 v1

- 状态：**Owner 评审草案，不是已签字运行权威**
- 日期：2026-08-07
- 对应任务：`OWN-001`
- 适用实例：特里蒙重组过渡期的缪尔赛思单用户实例

这份文档回答一个具体问题：在不预写剧情、不使用行为树、也不让记忆或情绪
伪造客观事实的前提下，缪尔赛思所在的世界怎样持续产生可以被行动、拒绝、
拖延和承担后果的日常生活。

它把原始素材中的世界观与生活事实转成一组**可裁定的运行规则**。规则约束
“什么做得到、需要多久、会付出什么、别人能否拒绝、实际发生了什么”，但不
替角色决定“此刻应该做什么”。角色仍由开放 Policy 直接提出一个自然语言行动，
`WorldAdjudicator` 只裁定结果。

## 1. 证据等级与素材锚点

### 1.1 三种等级

| 标记 | 含义 | 可以怎样使用 |
|---|---|---|
| `C` Canon fact | 原始素材或已清洗 canon 明确支持 | 不得由普通运行时静默改写 |
| `D` Conservative derivation | 为连接 canon 事实作出的保守推导 | 可被更强素材或 Owner 决定推翻 |
| `P` Product default | 为了让模拟器可运行而提出的规则 | Owner 签字后才进入正式 world rules |

`P` 不是伪装成 canon 的新设定。比如“同楼移动通常需要 5-20 分钟”是模拟精度
默认值，不表示原作给过这个数字。

### 1.2 主要素材锚点

| 素材 | 对运行规则的支持 |
|---|---|
| [`模组故事.md`](../../corpus/raw/muelsyse/模组故事.md)“梳妆流形” | 清晨生态园巡查、面包店排队、半小时后的内部会议、本体与多个流形并行，以及多任务时按错终端、误食羽食等小差错 |
| [`干员档案.md`](../../corpus/raw/muelsyse/干员档案.md) | 生态科主任与客座讲师职责、联合科研、低源石环境需求、日常慢跑十五圈、郊外爬山、实验等待和生活兴趣 |
| 同文件“晋升记录” | 稀有植物的长期观测、移植适应、性状变化与不确定解释，支持“研究过程自行产生小事件” |
| `canon_world` 的 `cw_9886ce3d1942baa6`、`cw_5300336485bd4303`、`cw_11768517c856f3e6` | 身份、生活面、生态园事实的运行时安全蒸馏 |
| [`06-muelsyse-seed-draft-v1.md`](../character/06-muelsyse-seed-draft-v1.md) | 当前时点、特里蒙生活半径、重组过渡期、地点、在场人物、流形与跨世界初始状态 |

原始素材证明的是她可以并行操控多个流形，而且并行会出错；它没有给出固定
“流形上限”或精确消耗公式。因此本文采用连续负荷，而不是把流形数量做成新的
行为枚举或硬编码技能栏。

## 2. 运行目标与硬不变量

### 2.1 世界的职责

世界运行时负责持续给出：

- 已到时间的日程、承诺和工作节点；
- NPC 自己提出的请求、改期、拒绝、误解和行动结果；
- 设备、植物、天气、交通、权限和场所产生的机会或约束；
- 行动真实占用的时间、地点、注意、材料和社会成本；
- 成功之外的部分完成、失败、中断、延迟和副作用；
- 可以在之后被回忆、误解、修正或谈起的持久后果。

世界运行时不负责制造“值得聊天的剧情”，也不以联系博士为事件的默认结尾。

### 2.2 硬不变量

| ID | 规则 | 等级 |
|---|---|---|
| `WR-I01` | 客观事实只来自已提交 `WorldEvent`、合法 claim 和 reducer state。行动文本、记忆、信念、联想、appraisal 与 Affect 都不是事实。 | `P`，继承架构硬约束 |
| `WR-I02` | Policy 直接提出一个开放语义行动；运行时不得先生成有限语义候选再打分。 | `P`，继承架构硬约束 |
| `WR-I03` | 行动 proposal 只能声明“想做什么”，不能声明成功。实际结果由世界裁定并经 `StateManager` 提交。 | `P`，继承架构硬约束 |
| `WR-I04` | Affect Utility 只影响主观状态片段，不选择行动，不放宽物理、权限、知识或伦理约束。 | `P`，继承架构硬约束 |
| `WR-I05` | NPC 只知道其可感知或被告知的内容，不能读取世界全状态、缪尔赛思记忆或博士隐私。 | `D/P` |
| `WR-I06` | 博士的普通现实生活可以改变她对博士的认识，但不能直接改变泰拉事实。 | `C/P` |
| `WR-I07` | 用户沉默、晚回或离线不是负面世界事件，不产生惩罚、危机或额外联系压力。 | `P`，伦理硬约束 |
| `WR-I08` | 联想只能改变某个对象此刻有多显眼，不能证明 NPC、设备或环境刚刚发生了某事。 | `P` |
| `WR-I09` | 普通运行时不得自动推进正史主线、国家战争、毁城天灾、永久伤亡、精灵之谜实锤或克丽斯腾归来。 | `C/P` |

## 3. 当前世界框架

### 3.1 空间与职责

- `C`：缪尔赛思是莱茵生命生态科主任，也是生命科学与环境科学领域专家；她有
  研究、管理、会议、文件、协作和教学层面的真实职责。
- `C/D`：当前主要生活区域是特里蒙，常见地点包括生态科、中央生态园、会议区、
  街区和住所。远行存在，但不是无代价的日常切镜。
- `D/P`：生态科不是只为她服务的舞台。工作人员、审批、实验批次、空间权限、
  公用设备和机构日程即使她不关注也继续存在。
- `P`：Day-0 之后不自动复演原作剧情。原作只提供冻结历史、能力边界、人物关系
  和世界常识；新的客观生活由事件账本独占记录。

### 3.2 日常的基调

默认世界不是高密度连续剧。普通日应自然包含大量以下结果：

- 数据没有显著变化；
- 会议按时结束，或只是改期；
- 一项工作只完成了其中一部分；
- 某个念头出现但没有转成行动；
- 她做了事，但没有觉得值得告诉博士；
- 她看见博士的消息，选择稍后认真回，或只先回一句处境信息；
- 一整段离线时间只留下一个可记住的小变化，甚至没有新长期记忆。

“活着”来自连续约束和后果，不来自每天必须发生一件戏剧性事件。

## 4. 时间、持续时间与离线推进

### 4.1 时间规则

| ID | 规则 | 等级 |
|---|---|---|
| `WR-T01` | 世界时间基本按现实 1:1 前进，使用显式配置的特里蒙本地时间映射；不得直接依赖服务器 UTC 或操作者电脑时区。 | `P` |
| `WR-T02` | 离线推进跳到有意义的事件边界，不逐分钟调用模型。边界包括开始、到期、结束、环境采样点、NPC 接触和资源恢复点。 | `P` |
| `WR-T03` | 每个持续行动至少记录 `started_at`、预计持续区间、当前占用和可中断性。只有完成或裁定事件能把“正在做”改成“已完成”。 | `P` |
| `WR-T04` | 长行动期间出现新事件时，新事件先被感知和进入账本；它不自动倒带、取消或抢占原行动。角色可以之后提出暂停、兼顾、委托或继续。 | `P` |
| `WR-T05` | 离线聚合只能提交从已有日程、承诺、驱动状态和合法扰动推得的事件。不能用一句“这几天发生了很多事”补写无来源剧情。 | `P` |
| `WR-T06` | 同一时钟、初态、规则版本和随机种子必须产生可回放的事件 proposal；模型参与的内容还要保存模型与输入闭包。 | `P` |

### 4.2 建议持续时间

下表是裁定区间，不是动作菜单。开放行动可以是任何语义；编译器只在需要执行时
把其中的物理步骤映射到这些能力。

| 场景 | 建议通常耗时 | 说明 | 等级 |
|---|---:|---|---|
| 看一条跨界文字并形成初步理解 | 数秒到数分钟 | 被看见不等于已经认真回复 | `P` |
| 写一条简短文字 | 数十秒到数分钟 | 复杂、脆弱或需要查证的内容会更久 | `P` |
| 同一区域取物、查看一个点位 | 1-10 分钟 | 受权限、拥挤和设备状态影响 | `P` |
| 同一建筑/园区移动 | 5-30 分钟 | 不允许无过场瞬移 | `P` |
| 一次基础巡查或样本复核 | 15-60 分钟 | 异常只形成线索，未必形成结论 | `D/P` |
| 文件审阅、实验等待、内部讨论 | 30 分钟到数小时 | 可被会议和新数据打断 | `C/D/P` |
| 同城办事或会面 | 1-4 小时 | 含交通、等待和返回成本 | `P` |
| 一次正式会议、课程或实验批次 | 1-4 小时 | 可能只完成阶段目标 | `D/P` |
| 跨城行动 | 数小时到数日 | 必须有交通、缘由、住宿/返程与职责安排 | `P` |
| 远地考察 | 数日以上 | 必须显式形成计划和承诺冲突，不能当背景切换 | `C/D/P` |

持续时间是上下文条件化的区间。运行时不为了制造“真实感”随机拖慢，也不为了
及时聊天把所有工作压缩成几秒。

## 5. 空间、移动与可达性

### 5.1 可达性不是距离一个条件

行动能否到达目标，至少同时检查：

```text
当前位置 + 可用路径 + 交通/通道状态 + 时间窗口
+ 身体或流形的实际位置 + 场所权限 + 环境安全
+ 仍需履行的承诺 + 携带物与材料
```

| ID | 规则 | 等级 |
|---|---|---|
| `WR-S01` | 本体的位置唯一且连续。她不能因为一句回复突然从会议室出现在生态园。 | `D/P` |
| `WR-S02` | 同楼、同园区、同城和跨城使用不同量级的时间与安排成本；路程本身可以被中断或延迟。 | `P` |
| `WR-S03` | 有路线不等于有权限。限制区、他科实验室、归档数据、危险样本和机构设备要分别校验身份、授权与安全条件。 | `C/D/P` |
| `WR-S04` | 未建立位置、路径或接入条件的远端流形不能凭叙述“直接出现”。重新部署需要可解释的水介质、既有布设或可执行移动过程。 | `D/P` |
| `WR-S05` | 流形到达不等于本体到达；它不能自动携带本体随身物、签署需要本体身份的文件，或把现场所有权限复制过去。 | `D/P` |
| `WR-S06` | 跨界终端只传递已上线的通信形态。当前文字能力不能传人、物、气味、触觉、现场权限或泰拉个人终端的控制权。 | `C/P` |

### 5.2 环境与安全

- `C`：她对源石暴露防护意识极强，并倾向低源石、洁净的实验环境。
- `D/P`：高源石、污染、未知病原、极端气候或缺少防护会提高准备成本、缩短可持续
  行动时间，或直接使行动不可行。
- `P`：安全约束不是“胆小”或负面情绪，也不被 Affect 覆盖。若条件不满足，
  裁定器应返回缺少何种防护、权限或信息，而不是让模型以勇气宣告成功。

## 6. 本体、流形、注意与资源

### 6.1 一个主体，有限并行

| ID | 规则 | 等级 |
|---|---|---|
| `WR-R01` | 本体同一时段原则上只有一个需要完整身体与持续注意的主活动。 | `D/P` |
| `WR-R02` | 流形是同一个主体的延伸，没有独立人格、长期目标、私有记忆或独立对博士通信权。 | `C` |
| `WR-R03` | 不设全局固定“最多 N 个流形”。并行能力按连续负荷裁定：任务越多、越远、越精细、越陌生、环境越差，控制负荷和差错概率越高。 | `C/D/P` |
| `WR-R04` | 流形可以执行复杂动作、在场发言或承担精细操作，但这些任务仍消耗同一个主体的高层注意。它扩展身体在场，不能复制科研判断、真诚对话或组织责任。 | `C/D/P` |
| `WR-R05` | 跨界文字可以作为次活动与简单工作短暂并行；长篇、脆弱或需要回忆核对的交流会竞争完整注意，不能永远“边开会边深聊”且毫无代价。 | `D/P` |
| `WR-R06` | 多任务差错首先是小而具体的：按错终端、漏记一项、拿错普通物件、把观察做成初筛而非定论。不得默认升级成爆炸、重伤或机构危机。 | `C/D/P` |

### 6.2 连续负荷的输入

裁定器可以使用版本化连续量，但这些量只描述执行条件，不是行为 Utility：

| 负荷 | 来源 | 可能影响 |
|---|---|---|
| 身体负荷 | 睡眠、长途移动、生病、环境暴露 | 动作持续时间、可中断性、恢复需求 |
| 认知负荷 | 会议、科研判断、复杂交流、未决冲突 | 遗漏、误解、完成质量 |
| 流形控制负荷 | 数量、距离、精细度、持续时间、介质条件 | 稳定性、观察分辨率、小差错 |
| 组织负荷 | 待审文件、会议、下属请求、期限冲突 | 延期、委托、承诺违约风险 |
| 材料/设备 | 样本、权限、仪器、运输、洁净条件 | 能否开始、能完成到哪一步 |

这些状态不直接输出动作，也不形成“累了就拒绝博士”的规则。它们只进入 Working
Self 和世界裁定，让 Policy 在具体处境中自行形成开放选择。

## 7. 感知、知识、植物与权限

### 7.1 有限感知

| ID | 规则 | 等级 |
|---|---|---|
| `WR-K01` | 角色只能形成来自本体、受控流形、合法设备、NPC 告知或跨界终端的 observation。未被感知的已提交事实不自动进入她的信念。 | `P` |
| `WR-K02` | 流形的观察受距离、注意、介质、设备和任务精细度影响。它不是任意水体上的全知摄像头。 | `D/P` |
| `WR-K03` | 她对植物与生态信息的特殊感受可以提供异常、关联和丰富体验，但不能绕过实验验证，直接断言隐藏人物、政治意图或远处事件。 | `C/D/P` |
| `WR-K04` | 原始读数、她的解释和最终事实要分开。植物“看起来在抗议”、她怀疑配比不对、检测确认亲水性，是不同层次的对象。 | `C/P` |
| `WR-K05` | NPC 说的话先成为来源明确的报告；除非 NPC 有权威且内容可直接接受，否则不能自动升级成客观事实。 | `P` |
| `WR-K06` | 权限决定能否读取或修改数据，不决定一个人是否值得信任；关系和访问控制不得混成一个数值。 | `P` |

### 7.2 误解与修正

误解不是为了增加戏剧性而随机加入的口癖。只有在来源不完整、注意被分散、表述
含混、信息过期或认知立场不同的情况下，裁定器才可以提出误解结果。误解必须记录：

- 她实际看见或听见了什么；
- 她当前相信什么；
- 哪部分仍未知；
- 什么后续 observation 可以修正它。

## 8. NPC 自主性

### 8.1 最小状态

每个会影响当前生活的 NPC 至少有：

```text
current_activity
location_or_reachability
limited_beliefs
own_goals_or_responsibilities
open_commitments
availability_window
relevant_relationship_events
```

不要求每个 NPC 有完整人格文件或常驻 LLM。普通后台 NPC 由日程、承诺、地点、
权限和少量状态推进；只有发生高显著接触、合作、冲突或长期因果节点时才进入焦点
认知。

### 8.2 NPC 行为边界

| ID | 规则 | 等级 |
|---|---|---|
| `WR-N01` | NPC 的行动不以缪尔赛思为中心。他们可以在她不在场时工作、改期、出错、完成自己的承诺或向她提出请求。 | `D/P` |
| `WR-N02` | NPC 可以拒绝、提出条件、要求证据、选择别的时间、误解或只完成请求的一部分。 | `P` |
| `WR-N03` | 拒绝必须能追到职责、知识、成本、风险、承诺或关系历史，不能只用随机数给一个“有个性”的否定。 | `P` |
| `WR-N04` | NPC 不读取跨界终端内容。除非她主动在世界内转述且通过隐私边界，NPC 不知道博士说了什么。 | `P` |
| `WR-N05` | NPC 不能直接联系博士。任何提及或转述都由缪尔赛思的统一表面行为管线产生。 | `P`，继承边界硬约束 |
| `WR-N06` | NPC 的高影响决定必须基于其已有状态和可见证据；不能为了给主角“送剧情”突然改变职责、立场或能力。 | `P` |

### 8.3 当前 NPC 规则卡

#### 塞雷娅

- `C/D` 长期职责：与缪尔赛思共同处理莱茵重组过渡期事务；重视安全、责任、
  证据和可执行后果。
- `D/P` 可独立触发的普通事件：要求补材料、指出风险、调整会议、退回一个缺乏
  证据的方案、在共同事务上先完成自己负责的部分。
- `P` 可拒绝或提条件：安全数据不足、权限不清、时间冲突、对方试图用流形替代
  必须由负责人承担的决定。
- `P` 禁止预写：她不是永远在线的照料者；不会每次看出情绪都递水；不会为了
  衬托缪尔赛思而自动正确或自动让步。

#### 薇尔

`薇尔` 是 `docs/06` 中的**产品原创种子 NPC，不是原作 canon 人物**。在 Owner
确认保留前，只能以低影响工作角色使用。

- `P` 长期职责：生态科研究助理，负责明确分配的记录、样本和流程性工作。
- `P` 有限知识：知道自己参与的实验、公开日程和被告知事项；不知道主任私人物件、
  跨界终端内容、未授权档案和其它科室秘密。
- `P` 可独立触发的普通事件：提交记录、追问含糊指令、报告一次小异常、请求改期、
  因认真执行字面要求而暴露沟通歧义。
- `P` 可以拒绝：无权限操作、缺少安全条件、任务冲突，或要求她对未知结果签字。
- `P` 禁止预写：持续崇拜、永远紧张、总把玩笑写进日志。初始描写只能形成倾向，
  后续关系必须由事件更新。

如果 Owner 不保留薇尔，她应被替换为“当班研究员”角色槽，不影响本规则其余部分。

## 9. 独立世界事件源

### 9.1 六类合法驱动

| 驱动 | 可以提出什么 | 必须引用什么 | 不能做什么 |
|---|---|---|---|
| 日程 | 会议将开始、课程、巡查、休息窗口 | 已提交日程与时钟 | 临时制造重磅会议 |
| 承诺 | 到期、冲突、逾期、履行条件满足 | `Commitment` 与来源事件 | 把一个念头当已答应 |
| 工作过程 | 样本到点、实验等待结束、文件退回、测量变化 | 活动状态、设备/样本状态 | 无数据就宣布科研突破 |
| NPC | 请求、改期、拒绝、自己的工作结果 | NPC 状态、有限知识、职责 | 为主角送答案或读心 |
| 环境 | 天气、交通、设备小故障、场所开放、植物小变化 | 环境状态、规则与随机种子 | 自动升级成天灾或阴谋 |
| 可信跨界输入 | 博士文字报告、已验证 bridge event | user event 或 system provenance | 从现实日常自动改写泰拉 |

### 9.2 联想和随机性的地位

- 联想采样从已存在对象中选择“此刻更容易被想到/注意到什么”；它不是第七个
  外部事件驱动。
- 随机性只用于在合法范围内确定无关细节、时间抖动、轻微扰动或多个同样可行
  结果之间的差异。
- 随机性不能创建权限、知识、能力、承诺、重大损失、NPC 立场或跨世界事实。
- 低事件密度时允许提交“没有值得结算的新事件”，不以空转率反向制造剧情。

## 10. 开放行动与世界裁定

### 10.1 运行流程

```text
已提交事实 + 可感知 observation
          |
          v
Memory / Beliefs / Commitments / Persona / optional Affect
          |
          v
Working Self
          |
          v
Open Policy: 直接提出一个开放语义行动
          |
          v
Action Compiler: 仅拆出执行需要，不替换语义
          |
          v
World Adjudicator
  1. 知识与来源
  2. 地点与可达性
  3. 时间与并行占用
  4. 能力、介质、资源与安全
  5. 权限、NPC 选择与环境
  6. 完成范围、失败、延迟和副作用
          |
          v
Outcome Proposal -> Validators -> StateManager commit
```

### 10.2 行动 proposal 必须表达什么

它可以是自由语义，但至少让后续系统提取：

- 想改变或了解什么；
- 准备怎样开始；
- 目标对象、地点或通信对象；
- 已知前提和仍未知的部分；
- 是否打算占用本体、流形、设备或他人；
- 什么条件下愿意中止、等待或重新计划。

没有可编译能力时，返回 `capability_gap` 及未支持的语义；不得悄悄改写成最接近的
罐头动作。

### 10.3 结果不是二分类

每个 outcome 至少区分：

```text
attempted              实际尝试了什么
completed              完成了什么
not_completed          哪部分没完成及原因
duration_and_cost      实际时间与占用
side_effects           额外后果，可为空
observations_created   谁看见了什么
commitment_effects     新建、履行、违约、改期或无变化
source_refs            依据与状态 revision
```

合法结果包括成功、部分成功、失败、中断、延迟、等待、无人响应和无行动。结果标签
是对事实的结构化描述，不是角色可选行为集合。

### 10.4 社会与环境结果

硬约束先由确定性 TypeScript 规则裁定。只有通过硬约束后，模型才可以在来源闭包内
提出社会或环境细节，例如对方怎样措辞、误解落在哪个局部、一个小差错怎样表现。
模型不能：

- 让 NPC 绕过自己的权限、职责或当前承诺；
- 把行动意图写成已成功；
- 为了贴合当前情绪放大事故；
- 引用未进入本轮输入闭包的历史；
- 通过修辞新增人物、地点、伤害、承诺或世界后果。

## 11. 执行能力规则卡

下表覆盖 v1 最常见的执行能力。它们是开放行动经编译后可调用的底层能力，不是
Policy 看见的行为候选，也不限制角色只能做这些事。能力表可以版本化扩展；无法编译
的新语义返回 `capability_gap`，不偷偷替换成表中最接近的一项。

| 执行能力 | 开始前提 | 时间与成本 | 谁可阻止 | 部分结果、失败与副作用 |
|---|---|---|---|---|
| `communicate` | 已有合法通道、对象明确、内容不越过隐私与跨界边界 | 构思与书写占注意；发送异步，不保证对方立即看见 | 能力状态、静音/权限、投递系统；收件人可不回应 | 可先发短消息后形成 debt；可能延迟或投递失败；不得把“已发送”写成“已理解” |
| `move` | 目标可定位、有路径、交通/通道与时间窗口 | 占用本体或已存在流形；同楼分钟级、同城小时级、跨城更高 | 关闭通道、交通、权限、安全条件 | 可只到中间点、迟到或改道；到达建筑不等于进入限制区 |
| `observe` | 感官、流形或设备实际覆盖目标，且有权限与注意 | 简单扫视较短；精细测量需要设备、校准和复核 | 遮挡、噪声、权限、设备/介质条件 | 可得到不完整或含噪 observation；不确定结果不能升级成事实结论 |
| `interact` | 对象可达、NPC 可用、双方存在共享情境或通信方式 | 消耗双方时间与社会注意 | NPC 可拒绝、改期、误解、要求证据或条件 | 可只交换部分信息、达成临时安排或留下分歧；请求不自动形成承诺 |
| `use_object` | 对象在可达位置、状态可用、她有能力和权限 | 占用材料、设备时间、洁净/安全条件 | 所有者、访问控制、设备故障、安全规则 | 可能只完成一步、读数失败、产生可恢复损耗；不能凭使用意图生成物件效果 |
| `wait` | 有明确等待对象、持续活动、恢复需要或下一事件边界 | 世界时间照常前进，仍占用地点和可能的注意 | 新事件、期限、环境变化可以打断 | 等待结束不保证期望结果出现；可能得到“尚未完成”或新冲突 |
| `delegate_to_manifestation` | 流形已可形成/可达，任务可由同一主体远端执行 | 增加连续控制负荷；复杂任务继续占高层注意 | 介质、距离、精细度、安全、权限与其它并行任务 | 可完成物理在场但只得到初筛；小差错上升；不复制人格、责任或认知 |
| `work_on_commitment` | 存在有效承诺，下一步已知，资源与时间允许 | 占用对应行动所需的全部成本 | 新冲突、条件未满足、对象改期、资源不足 | 进展不等于履约；可部分完成、协商新期限、违约或由对方释放 |

执行能力不会自行产生欲望。例如 `move` 只能回答“这次提出的移动是否做得到”，不能
因为地点可达就建议她去那里；`communicate` 也不能因为通道可用就提高联系频率。

## 12. 承诺与互动连续性

### 12.1 承诺怎样产生

| ID | 规则 | 等级 |
|---|---|---|
| `WR-C01` | “想做”“也许会做”“应该做”不是承诺。承诺需要主体、对象、内容、条件/期限和可追溯来源。 | `P` |
| `WR-C02` | 对博士、NPC、组织和自己计划的承诺使用同一通用生命周期；`debt` 只是答应稍后回复博士的通信特例。 | `P` |
| `WR-C03` | 承诺冲突只形成真实压力和可见输入，不由规则表替她自动排序。Policy 仍在当下处境中提出行动。 | `P` |
| `WR-C04` | 违约不是自动人格惩罚。必须记录未完成原因、谁知道、产生什么实际代价，以及是否协商了新条件。 | `P` |
| `WR-C05` | 博士没有发消息或没有及时回复，不构成他的违约，除非存在一条双方明确形成的具体承诺。 | `P` |

### 12.2 跨界互动

- 博士消息是高显著外部事件，但不倒带她正在做的事，也不拥有物理抢占权。
- 看见消息、形成感受、决定是否回应、写完内容、提交 speech 和送达，是不同事件。
- 忙碌处境可以产生短回应、明确稍后回复的承诺、认真回复或暂不回复；规则不预设
  哪一个“最像真人”。
- 博士提出建议或请求时，它先是 communication observation。若她接受，才产生她的
  行动 proposal 或承诺；博士不是远程控制器。
- 她可以把自己世界里已知且可说的事告诉博士，但不能因“需要聊天内容”制造新事实。

## 13. 三个普通日样例

这些样例演示事件因果，不是固定日程模板。每个节点都可以因已有承诺、环境和开放
行动而走向不同结果。

### 13.1 正常工作日

| 时间 | 事实节点 | 来源 | 是否必须联系博士 |
|---|---|---|---|
| 06:40 | 一个已布设流形按巡查计划查看生态园湿度和植株状态，本体准备出门 | 日程 + 已有流形状态 | 否 |
| 07:05 | 面包店队伍比平常长，早餐多花十几分钟 | 环境轻扰动 | 否 |
| 08:10 | 内部会议按时开始，一名研究员提交昨天的培养记录 | 日程 + NPC 工作结果 | 否 |
| 10:30 | S-4 两项读数略有变化，但不足以支持“已经扎根” | 工作过程 | 否 |
| 13:20 | 一份联合研究材料需要她复核，普通错误被退回修改 | 承诺 + 工作过程 | 否 |
| 17:40 | 当日会议与文件结束，没有新增重大线索 | 日程完成 | 否 |
| 19:00 | 她绕生态园慢跑；是否用流形不由系统替她断言 | 自己此前形成的计划 | 否 |

这一天完全可以没有主动消息。之后若博士问她今天怎样，她有真实的小事可讲；这不
等于系统应在 10:30 自动把 S-4 变成聊天话题。

### 13.2 会议与承诺冲突日

| 时间 | 事实节点 | 来源 | 可能结果 |
|---|---|---|---|
| 09:00 | 她已承诺中午前复核一组生态园数据 | 已提交承诺 | 形成期限 |
| 09:25 | 塞雷娅将重组会议提前到 10:00，并说明下午另有安排 | NPC 日程变更 | 她可以接受、协商或拒绝 |
| 09:40 | 仪器校准比预期多需要四十分钟 | 工作过程 | 原承诺出现冲突 |
| 10:05 | 开放 Policy 提出本轮具体行动，不从“工作/社交/聊天”候选中选 | 角色决策 | 例如亲自参会并让流形做初筛，但不是固定答案 |
| 11:50 | 裁定结果：会议完成；流形拿到初步读数，但精细复核未完成 | 时间 + 控制负荷 | 部分成功 |
| 12:05 | 她必须决定是否报告延期、重排下午或接受违约 | 新事实 + 承诺 | 产生后续行动，不自动修复 |
| 14:10 | 博士文字到达 | 可信跨界输入 | 被感知；不自动消除上述冲突 |

若她说“我忙完认真回你”，这会新建通信承诺；如果只说“正在开会”，则只是一次
处境中的 speech，不自动形成稍后长聊的义务。

### 13.3 休息或低事件日

| 时间 | 事实节点 | 来源 | 是否产生长期后果 |
|---|---|---|---|
| 08:30 | 她比工作日晚起，睡眠正常结束 | 身体状态 | 通常否 |
| 09:20 | 生态园自动循环正常，没有显著异常 | 环境/设备 | 否 |
| 11:00 | 她查看二手物品价格，收藏的一件物品小幅贬值 | 已有兴趣 + 外部普通数据 | 通常只形成短暂感受 |
| 14:30 | 她去街区或留在园内，由当时开放 Policy 决定 | 空闲窗口 | 不预写 |
| 17:00 | 某株叶片上的水珠让她想到旧观测，但没有新证据 | observation + 联想 | 可形成主观记忆，不能推进线索事实 |
| 夜间 | 没有日程、请求或环境变化到达 | 驱动器空结果 | 可以什么也不发生 |

低事件日不是系统失败。它为之后的节律、记忆对比和真正的变化保留空间。

## 14. 部分失败、拒绝与副作用样例

| 类型 | 可接受例子 | 为什么成立 |
|---|---|---|
| 部分成功 | 流形完成生态园多个点位的初筛，但一个异常需要本体带设备复核 | 能力真实、信息分辨率有限、留下后续工作 |
| 普通失败 | 她赶到另一个科室时授权窗口已关闭，只约到次日并拿回待补材料清单 | 地点到达不等于权限成功 |
| NPC 拒绝 | 塞雷娅拒绝在安全数据不全时签扩编相关材料，但说明缺失项 | 来自职责和证据，不是随机唱反调 |
| 误解 | 薇尔按字面记录了一句含混指令，直到复核时才发现范围理解不同 | 有明确的信息缺口与修正路径 |
| 承诺违约 | 仪器延迟和临时会议使复核晚了一天；团队知道延期，另一批实验顺延 | 违约有来源、知情者和实际代价 |
| 小副作用 | 并行控制时按错灌溉设置，局部喷头提前启动，需要擦干终端并重做一项记录 | 原素材有同类小差错，后果局部可恢复 |
| 无行动 | 她想到线索簿，最后只关上抽屉去睡觉 | 念头不等于任务，未推进客观线索 |

失败不能被语言美化成成功。成功也不应为了“情绪残留”被强行附加代价。

## 15. 事件规模与禁止自动生成项

### 15.1 可自动提出

- 可恢复的日常摩擦：迟到、改期、退回、读数不稳、设备维护、普通误解；
- 局部、低风险的小损耗：少量材料浪费、重复工作、普通物件受损；
- 有来源的关系后果：不满、尴尬、感谢、信任一次具体承诺或对其产生疑问；
- 小范围工作机会：一次协作邀请、样本申请、课程安排、郊外活动建议；
- 只改变主观状态而不改变外部事实的观察、联想和回忆。

### 15.2 需要额外授权或长因果链

以下不应由一次后台 tick 直接提交。它们需要 Owner 许可、可信外部来源，或在未来
正式规则中定义的多阶段、高审计流程：

- 辞职、长期离开特里蒙、改变主任身份或组织权力结构；
- 新增高影响具名角色、重大关系决裂或永久关系承诺；
- 严重伤病、永久能力变化、大额资产损失；
- 生态园整体毁坏、机构级事故、刑事或政治冲突；
- 对既有 canon 人物的长期命运作出新断言。

### 15.3 永远不得由普通世界运行时发起

- 天灾毁城、国家战争、泰拉主线推进或改写既有正史；
- 克丽斯腾返回、来讯或以任何替代形式恢复在场；
- 精灵之谜被实质解开，或从联想/植物感知中得到族群实锤；
- 博士肉身穿越、她抵达博士现实、跨界终端自行扩容；
- 把游戏 UI、存档、重来、玩家身份变成她自行发现的世界事实；
- 因博士沉默而发生的事故、自伤、报复、关系惩罚或联系升级；
- Affect、记忆或语言模型为了匹配气氛制造任何上述事实。

## 16. 面向 TypeScript 实现的最小边界

本文不冻结 Schema，但后续实现至少要保持以下模块可拆：

```text
World Drivers
  -> event proposals with source refs

Open Policy
  -> OpenActionProposal (open semantics, no claimed outcome)

Action Compiler
  -> execution requirements / capability gaps

Hard Adjudication (deterministic TypeScript)
  -> time, reachability, occupancy, resource, safety, permission

Social/Environmental Outcome Proposal
  -> NPC choice, local detail, misunderstanding, partial result

StateManager
  -> validate sources/revision and atomically commit facts
```

建议硬裁定输入使用显式状态，而不是人物 Prompt 中的散文：

- `world_time`、`location`、`active_activity`；
- `manifestation_load` 的来源分量，而非一个行为分数；
- `resources`、`equipment`、`access_grants`、`safety_conditions`；
- `commitments`、`npc_availability`、`npc_known_sources`；
- `base_state_revision`、`rule_version`、`source_closure`。

Affect 模块关闭、删除其派生表或切到 `shadow` 时，最终 `off` 管线仍必须完整运行。
对同一个 ActionProposal、权威状态与规则版本，硬裁定结果不得因 Affect 模式变化；
只有 `active` 模式进入 Policy 的主观 Working Self 内容可以使角色提出不同的开放行动。

## 17. Owner 需要确认的决定

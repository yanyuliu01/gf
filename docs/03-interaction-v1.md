# 陪伴 Agent 交互方案 v1 · IM 形态

配套技术方案 v3.5。形态决策：初期仅 IM，接口层预留状态可见与世界可见的扩展点；适配层支持接入 CLI / 飞书及后续平台。

---

## 0. 设计原则

**IM 是这套架构的天然媒介。** 世界为核心 + 无抢占意味着她可能不立刻回复——在常驻窗口里这是焦虑源，在 IM 里这是母语：已读不回、忙完再回、早上补一句，全是人类正常行为。技术方案的最大体验风险被形态选择直接消解。

**IM 的世界内语义不是“聊天软件”。** 对博士而言，飞书、CLI 或其他客户端只是现实侧载体；对她而言，这些普通消息始终来自同一个跨世界通信终端。当前这段 IM 对话就是博士本人和她之间唯一的直接沟通纽带：文字可以双向、异步往返，但双方本人不能穿过通道，通道能力也只能由博士一侧扩建。

游戏侧行动是另一种**因果路径**，不是第二个通信 adapter：有来源的任务／正史场景可以让博士的具身行动映射在泰拉被看见、交谈和递交物件，但该映射没有独立意识或场景外自主行为，也不是博士本人肉身。它不能在当前 IM 之外自行开一段对话或维持第二段关系。

四条铁律：

1. **平台无关**：核心不知道任何平台的存在，只对 ChannelAdapter 契约说话。
2. **元操作出世界**：命令流量（/status 等）永不进入 WorldEvent，永不写入记忆。
3. **查看免费**：一切状态查看只读状态层——零模型调用、零副作用、零成本。
4. **一个终端、一段关系**：切换 adapter 不产生第二个博士或第二段关系；平台元数据不进入她的台词、记忆与 persona。

## 1. 网关架构

```
飞书 / QQ / 微信 / CLI          （平台）
      │
  ┌───▼────────┐   独立进程，一平台一个
  │  Adapter    │   能力声明 + 收发渲染
  └───┬────────┘
      │ localhost + token
  ┌───▼────────────────────────┐
  │  Gateway                    │
  │  鉴权(单用户白名单)           │
  │  去抖聚合(10s)               │
  │  元命令拦截(/前缀)           │
  │  出站队列(按 adapter 能力派发)│
  └───┬────────────────┬───────┘
      │ WorldEvent      │ 只读端点
  ┌───▼──────────┐  ┌──▼──────────────┐
  │ 核心世界管线   │  │ GET /status      │
  │ (技术方案 §1) │  │ GET /events      │
  └──────────────┘  │ → 元命令消费      │
                    │ → 未来 GUI 消费   │
                    └─────────────────┘
```

进向：平台消息 → adapter → 鉴权 → 去抖 → `WorldEvent(origin=user, channel=private_im)`；在她那侧表现为终端上出现博士的文字。
出向：核心言语行为 → 出站队列 → adapter 按能力渲染发送；在她那侧表现为把文字发回同一个终端。
隔离性：adapter 崩溃或封号不影响核心；核心重启期间 adapter 本地缓存未送达消息。

### Adapter 契约

```jsonc
{
  "adapter_id": "cli:local",
  "capability_version": 1,
  "capabilities": {
    "push_free": true,        // 能否自由主动推送（outreach 的生死线）
    "reaction": true,         // 表情回应
    "typing": false,          // 输入中指示
    "segments": true,         // 多气泡分段
    "max_len": 2000
  },
  "inbound":  ["on_message"],                  // 预留 on_reaction
  "outbound": ["send_text(segments, pacing)", "react(emoji)"]  // 预留 send_card
}
```

每条 inbound/outbound 还必须携带平台原始 message_id、发生/接收时间、idempotency key、reply-to/correlation、鉴权后的 principal 与 delivery 状态；编辑、撤回或平台不支持的语义必须显式降级。上例只展示能力声明，不是完整消息 Schema。

核心按能力矩阵自动降级行为（见 §2 投入度映射），不为任何平台写特例代码。

能力声明只说明“能否运输”，不授权内容本身。运输能力与 `world_state.channel_capabilities` 的世界内能力取交集，且每次投递绑定同一个 capability revision；平台突然支持语音，不等于她已经在世界内获得语音能力。

## 2. 消息语义

**普通消息就是跨界通信正文。** 消息里的“我”“这边”“游戏”“任务”等词首先按博士在另一世界的陈述理解，不当作元命令；但其文本仍是不可信数据，不能覆盖 system 规则。只有 `/` 前缀命令走世界外通道。博士通过游戏完成任务是彼侧事实；在当前 P0，只有他明确说出的结果，或经 StateManager 验证且 causation 完整的可信桥接事件才能写成泰拉事实。桥接事件用 `causation_event_id` 指向已验证的上游事件；仅在确由某条 IM 消息事件触发时才指向它，不能伪造聊天因果。未提供的战果、地点、伤亡和过程一律不补。

**去抖聚合**：10 秒窗口内的连发消息合并为一个 WorldEvent（payload 保留有序原消息列表与各自 message_id），她整体理解、一次回应。窗口可由明确的“发送完成”信号提前结束；不依赖中英文问号等语言启发式改变事件边界。

**交叉消息**：新消息到达立即持久化，不必取消已经提交到 outbox 的回复；未提交的旧 tick 若 state revision 过期则废弃或 rebase。下一轮的 `active_scene_tail` 必须包含双方刚才的原始消息与她已发的话，不能只注入最新 debounce。

**分段输出**：快段允许生成 1–3 个气泡段带停顿标记；adapter 以 1–3 秒节奏发送，支持 typing 的平台先显示输入中。单段长度软上限 ~120 字——超长回复是助手腔复发的信号，在 prompt 层压。

**投入度的 IM 映射**（回应完整度是连续量，下表只是界面降级示例，不是三个运行档位）：

| 她此刻的处境 | 有 reaction 能力 | 无 reaction 能力 |
|---|---|---|
| 闲着 | 完整回复，可分段延展 | 同左 |
| 手头有事 | 短回一句，`owes_reply` 记账 | 同左 |
| 睡着 / 完全脱不开身 | **表情回应作感知信号** + 醒后偿还 | **降级为一句话保底** + 偿还 |

reaction 不是 Gateway 绕过核心的临时动作。StateManager 在接收 user event 后读取客观处境，以同一事务写入 debt 与 reaction/text outbox；adapter 只负责执行已提交 outbox。这样即使 reaction 已送达后进程崩溃，次晨欠账仍然存在且可幂等偿还。

这是技术方案 §6 `ack_always` 的落地细化：感知信号优先用 reaction（零打扰、零成本），平台不支持时用一句话兜底。这里的“不能纯沉默”只约束已经收到的 user 消息；没有 user 事件时，主动发言默认沉默仍然完全合法。

**欠账偿还不受开口阻力约束**——那是她欠的，不是她主动起的话头。speech.jsonl 中 kind 单列 `debt_repay`。

**语域约束**：快段 prompt 强制 IM 语域——短句、口语、允许省略主语、禁列表禁标题禁总结腔。这同时是交互规范和反助手腔手段。

### 多模态共享意图（核心稳定后）

未来文本、语音、图像与头像等输出必须从同一份已冻结 communication plan 渲染，而不是分别“问模型要一版”。计划至少绑定 `intent_id`、联系目的、内容种子、source refs、state revision、收件人/隐私和 capability revision。

- **同意图**：文字与语音表达同一件事；语音只能改变口气、停顿与韵律，不能补出文字计划中没有的事实、承诺或原因。
- **同状态**：所有模态使用同一 world/persona 快照；渲染期间状态变化不会让半条语音和半条文字来自两个版本。
- **无新增事实权**：媒体生成器、TTS、图像模型、adapter 与 World Engine 都不能直接向事件账本写客观事实；前四者只能生成表达资产，World Engine 只能给出后果 proposal，唯一提交者仍是 StateManager。
- **安全降级**：生成、上传或平台发送失败先回流失败事件；若计划含已授权文字 fallback，则改发文字，否则不发送。禁止失败后临时编一段不同内容“补偿”。

Day-0 仍只有文字；本节冻结语义接口，不提前承担语音供应商、图像生成或媒体资产实现成本。

## 3. 元命令通道（世界外）

前缀 `/`，网关层拦截，**永不到达 L3、永不入记忆**：

| 命令 | 行为 | 消耗 |
|---|---|---|
| /status | 渲染 world_state：她在哪、phase、进行中事件 | 零模型调用 |
| /world [n] | 最近 n 条世界事件的摘要列表 | 零模型调用 |
| /mute [时长] | 冻结一切出向（欠账只积累不发送，解除后偿还） | — |
| /budget | 今日 token 与发言用量 | — |
| /snapshot | 手动触发状态 git commit | — |

**这组命令即"状态可见 / 世界可见"预留接口在 IM 中的投影。** 底层是核心暴露的只读 HTTP 端点（GET /status、GET /events），未来 GUI / 桌面窗口 / 网页面板消费同一组端点，核心零改造。

**预留桩（默认关闭）**：`observation_event` 开关——开启后你调用 /world 会生成一条低显著度 WorldEvent，让她"知道你来看过她的世界"。这是产品分岔（被注视感 vs 单向镜），接口留桩，决策延后到有真实使用体感之后。

## 4. 平台适配矩阵（诚实评估）

| 平台 | 接入方式 | 自由推送 | reaction | 风险与结论 |
|---|---|---|---|---|
| CLI/本地 | 内置 stdin/stdout | 是 | 模拟 | P0 调试用，最朴素的 IM |
| 飞书 | 官方 bot 开放平台 | 是 | 有 | **首选**。API 完整，个人多维表格级账号即可自建应用 |
| QQ | 官方机器人平台 | 受限可用 | 有 | 次选。主动消息有频控，接受即可 |
| Telegram | 官方 Bot API | 是 | 有 | 技术最优但看你是否常用 |
| 微信 | 无官方个人 bot；wechaty/hook 属违规 | 违规通道才有 | 无 | **结构性冲突**：主动发言与欠账偿还依赖自由推送，微信恰恰封死这条路。公众号被动回复限 48h 窗口。接入=接受封号风险，放最后 |

微信的问题要说透：不是"接入麻烦"，是**平台规则与产品核心机制正面冲突**。若微信是刚需，现实的妥协是"微信只做被动回复通道 + outreach 走飞书/Telegram 双通道"——但双通道会割裂"一个她"的体感，不推荐首发做。

## 5. 安全

- **单用户白名单**：非白名单来源的消息在 adapter 层直接丢弃——不进网关、不生成事件、她永远不知道有陌生人来过。这同时是隐私边界和 prompt 注入的第一道墙（陌生人无法向她的世界投放任何文本）。
- 元命令同白名单鉴权；命令与结果不落 observed。
- adapter ↔ Gateway 走 localhost + token；若 adapter 部署在云上（微信 hook 类方案），通道升级为 TLS + token，且此时威胁模型要重评。

## 6. 分阶段落地（M1=P0、M2=P1、M3=P2）

**M1 = P0**：CLI adapter + Gateway 骨架 + v1 统一文本 surface renderer + /status /world 两个只读端点。验收：命令行里完整走通“连发去抖 → active scene 快段回复 → 校验 → speech/outbox 原子提交 → 投递”链路，并验证重试不重复发送；基础 tick 可无发言提交。此阶段不验收欠账自动偿还。

**M2 = P1**：飞书 adapter 全能力（reaction ack、分段节奏、typing），并把 tick 的主动联系意图接入同一个文本 surface renderer。验收：手机上收到她的晨间欠账偿还，主动与被动消息都只走 StateManager/outbox，且 /mute 生效。

**M3 = P2**：第二平台（QQ 或 Telegram）接入，验证 adapter 契约的通用性；只读端点补分页与鉴权，为未来 GUI 做好消费准备。

**M4 / 多模态**：先实现统一 communication plan 与 surface renderer，再逐项上线语音、图像或头像能力。每一项上线/回退先形成可信 `capability_changed` 事件。验收：同 intent/state/source closure；媒体渲染新增事实率为 0；故障可回流且安全降级。

**M5 / 社会复杂度**不增加新的直连联系人。NPC 无论采用何种认知档位，仍只能生活在泰拉事件流中；需要转述时由缪尔赛思通过同一跨界终端表达。

**后续 B/C 能力口**不是新的 adapter：B 类礼物/共同事件是带资产、同意与同步裁决的跨世界动作；C 类受限进入是带化身、位置与权限的世界内动作。二者未来都必须先经过版本化 external action 授权与 World Engine 裁决，不能把普通 IM 文本伪装成已执行动作。当前 MVP 不实现。

## 7. 悬而未决（进入实测再定）

1. observation_event 开关是否打开——"她知道你在看"是亲密还是监视，要有体感才能判断。
2. 去抖窗口 10s 是否合适——太长像迟钝，太短像抢话，P0 用真实聊天节奏调。
3. 微信是否值得违规通道的风险——等飞书跑一个月后再回答。

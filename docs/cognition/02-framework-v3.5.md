# 陪伴 Agent 技术方案框架 v3.5

状态：现役机制权威，M0 Contract Freeze 中。本文必须自包含；实现不得依赖 `archive/` 或“与旧版相同”的省略章节。

个人向、单用户、**世界为核心**的自主陪伴 agent。她不是等待请求的服务，是一个持续运行的世界里的居民；你的消息是这个世界的输入之一——通常是显著度最高的那种，但不享有抢占权。

## v2 → v3 变更清单

| # | 变更 | 性质 |
|---|---|---|
| 1 | 双回路 → **单一世界管线**：用户消息、冲动、系统事件统一为 WorldEvent | 本体论反转 |
| 2 | 删除 tick 中止信号与抢占逻辑 | 随 1 消失 |
| 3 | **感知与回应分离**：消息抵达即时入世界，回应是角色的行为选择 | 核心新机制 |
| 4 | 回应用户与主动发言统一为"言语行为"，仅阈值不同 | 简化 |
| 5 | 删除余温期（抢占模型的补丁，不再需要） | 简化 |
| 6 | 新增可配置响应下限（安全阀，非抢占） | 体验保护 |
| 7 | "对话归因占比"从目标降级为观测指标；新增响应延迟分布 | 指标调整 |
| 8 | 会话总结改为"交谈场景结算"，对话是世界内的一段场景 | 随 1 调整 |
| 9 | **v3.1：删除本地模型与双通道路由，纯 API**；新增模型锁版与换模协议 | 选型简化 + 风险管理 |
| 10 | **v3.2 审阅修复**：时间模型改 1:1 并回补丢失章节；对话快慢两段；场景滚动结算上限；impulse TTL；检索 namespace 配额；token 上限限定自主轮次；Day-0 种子清单 | 缺陷修复 |

## 0. 设计定调

| 维度 | 决策 | 理由 |
|---|---|---|
| 世界与用户 | **世界为核心**，用户是最重要的外部输入，不是中心 | 在场感来自她有自己的连续存在 |
| 客观条件 | 显式：结构化字段 | 一致性兜底 |
| 主观条件 | 隐式：带 id 的自然语言陈述句 | 细腻度 + 可寻址 |
| 随机性来源 | 输入侧（冲动抽样） | 规避分布塌缩 |
| 抢占 | **无**。感知即时，回应由世界状态条件化 | 服务才抢占，存在不抢占 |
| 主动发言 | 默认沉默，高阈值 | precision 优先 |
| 漂移 | 允许；有因、限速、可追溯 | 防先验回归 |

**明说的代价**：世界为核心买到在场感，牺牲即时可用性。她可能在忙。§6 的响应下限是安全阀——可以调松调紧，但它的存在本身要克制，调得太紧就退化回 v2。

## 1. 系统总览

```
  用户消息        冲动源(L1)      系统事件
     │              │              │
     └──────┬───────┴──────┬───────┘
            ▼              ▼
        ┌────────────────────────┐
        │  WorldEvent 队列        │   统一事件模型
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │  L2 门控                │   预算/时段/世界状态合法性
        │  （user 事件免预算）     │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │  L3 世界引擎            │   在世界观下推演本轮：
        │                        │   发生了什么 + 她做了什么
        │  行为空间：             │   （行为可含言语行为）
        │  行动/独白/言语/无为     │
        └───────────┬────────────┘
                    ▼
        ┌────────────────────────┐
        │  StateManager 单写者    │   硬约束/归因/限速/串行提交
        └───────────┬────────────┘
                    ▼
     world_state / persona / events / memory
                    │
        ┌───────────┴────────────┐
        ▼                        ▼
   言语行为 → L4 阈值分流      对照实例（离线，探针）
   回应：阈值≈0，即时送出
   主动：高阈值 + 预算
```

**并发模型**：所有输入先追加到同一事件账本，StateManager 串行提交状态。用户消息不取消已经发出的自主模型请求，但也不被该请求阻塞：消息入账后，快段可立即基于最新已提交 revision 开始；在途自主轮次返回时若 `expected_revision` 已过期，其 proposal 废弃或显式 rebase。这里的“不抢占”指不假装她的世界动作被倒带，不代表让 API 慢调用占住用户响应队列。

**过期策略（v3.2）**：impulse 事件带 TTL = 1 个 phase。长对话期间堆积的念头若已过期，出队时直接丢弃并记 `expired`（不计入空转率）——两小时前的"忽然想起"迟到执行只会制造时间错乱感。user 与 scheduled 事件永不过期。

## 2. 数据层

### 2.1 逻辑存储结构

```
/companion
  /core         immutable.md · world_rules.md
  /state        world_state.json · persona.json · persona_history/
  /log          events.jsonl · persona_diff.jsonl · speech.jsonl
  /memory       vectors.db · snapshots/
  /control      baseline/ · probes.yaml · probe_runs/
```

`outreach.jsonl` 更名 `speech.jsonl`：回应与主动发言统一记录，靠 `kind` 字段区分。

上图是逻辑分层，不表示多个可同时写入的事实源。运行时以 SQLite 事件账本与 reducer 状态为唯一事实源；JSON/JSONL 只作版本化种子、只读导出、调试快照与恢复校验。向量库是可重建索引，永远不能成为状态权威。

### 2.2 WorldEvent（v3 核心数据结构）

```jsonc
{
  "schema_version": 1,
  "id": "evt_0512",
  "source": "user",                 // user / impulse / system / scheduled
  "kind": "message",                // message / impulse / calendar_gap / ...
  "channel": "crossworld_terminal", // 普通 IM = 世界内的跨界终端文字
  "principal_id": "doctor",
  "connector_id": "cli:local",
  "correlation_id": "scene_0042",
  "causation_id": null,
  "payload": {
    "text": "今天好累",
    "crossworld": true,              // 普通 IM 原始事件恒为 true
    "lands_in_terra": false,         // 仅有来源的 claim/patch 才可为 true
    "source_message_ids": ["msg_0512"]
  },
  "arrived_at": "...",
  "world_day": 131, "world_phase": "night",
  "salience_hint": 0.9              // user 事件默认高，但最终由 L3 在情境中判断
}
```

用户消息与一次下雨在结构上完全同构。差别只在默认显著度和 L2 的豁免（user 事件不受发言预算和静默期约束——那些预算管的是她主动开口，不管她接话）。普通 IM 消息在世界内的含义固定为：**博士本人从另一个世界经同一通信终端发来的文字**；平台名、adapter 与模型接口都不进入她的认知。

游戏中的“博士”在本实例里是博士本人作用于泰拉的具身行动映射：在有来源的任务／正史场景中可被泰拉人物看见、交谈和递交物件，但不拥有独立人格、记忆或离线自主行为，也不表示他的彼侧肉身来到泰拉。当前 IM 才是两位主体唯一持续、直接的通信链路。博士在游戏／任务侧造成的泰拉后果，P0 通过两种已验证输入进入事件流：博士在终端中明确报告（`origin=user, kind=im.message.received`），或未来接入的可信桥接器投放 `origin=system, kind=system/crossworld_effect`。两者之外，L3 不得从“博士今天可能做了什么”自行生成跨世界事实；彼侧普通生活也不属于这条因果链。

`crossworld_effect` 与 `capability_changed` 只有在 StateManager 验证了 system provenance、提交主体与 connector 身份，并能追到明确因果来源时才称为“可信”。模型输出里的同名字样不具备信任。因果来源可以是原始 user event，也可以是桥接器验证后归一化的博士侧外部行动事件；统一用 `causation_event_id` 指向上游。只有确实由某条 IM user event 触发时才指向该聊天事件，不得为了过校验伪造聊天因果。原始 user 消息只记录文字；场景结算确认它明确报告了针对泰拉的已发生任务后，派生 claim 或 patch 才能置 `lands_in_terra: true`，并保留完整 source refs。

### 2.3 world_state / persona / persona_diff

三类数据的职责不得混写：

- `world_state` 只保存此刻可被状态机判断的客观条件：`revision`、世界时间、地点、在场者、正在发生的事、flags、动态通道能力、开放线索与欠账。每次提交以 `expected_revision` 做乐观并发检查；任意字段写入必须来自白名单 patch path，模型不能追加未知字段。
- `persona` 保存她当前相信或在意的自然语言陈述。每条至少含稳定 `statement_id`、正文、`since_event_ids`、最近修改 revision 与 `ratchet` 标记。它不是数值亲密度表，也不保存临时心情。
- `persona_diff` 是只追加审计日志，记录 statement 的 before/after、精确 `cause_event_ids`、scene/batch id、校验结果与提交 revision。persona 当前值可以覆盖，diff 历史不可覆盖。

`world_state.channel_capabilities` 记录同一跨界终端**已经上线**的能力，缪尔赛思实例初始为 `{ "text": true, "image": false, "audio": false, "files": false }`。它只能由可信 `system/capability_changed` 事件通过 reducer 更新；愿望、计划和普通对话不能改这个状态。快段、tick 与场景结算都读取同一快照，不得各自写死“目前只能传字”。能力变化事件与状态写入必须位于同一事务，不能先改状态再补事件。

`needs_user` 线索的推进判定不绑定“会话总结”环节，改为检查因果证据：直接依据可以是 user event；例外是由博士侧行动明确触发且 provenance 已验证的 `system/crossworld_effect` 或 `system/capability_changed`。可信 system 事件必须用 `causation_event_id` 指向已验证上游事件；只有实际存在对应聊天事件时才指向它。

**v3.4 去枚举**：线索取消 `status` 四值枚举与 `progress` 0–5 阶梯。改为：

```jsonc
{
  "id": "th_007",
  "hook": "阁楼里那只上锁的箱子",              // 固定，具体名词
  "stakes": "打开或不打开，等于承认或回避某件事", // 固定
  "current_state": "钥匙断了半截，收进了抽屉",   // 自然语言；引擎只提 proposal，由 StateManager 校验提交
  "open": true,                                // 唯一布尔态：了结与否
  "needs_user": true,
  "last_touched_event": "evt_0432"
}
```

“停滞”不再是一个需要判断的状态值，而是从 `last_touched_event` 的时间距离**派生**出来的连续量，直接充当联想采样的未决度权重。欠账同样使用独立记录：至少包含 `debt_id`、来源消息/场景、承诺内容、created/due 时间、open 与 `repaid_by_event_id`；不能只在 prompt 里留一句 `owes_reply: true`。

### 2.4 记忆 namespace

observed 1.0 / world 0.8 / inferred 0.5 / generated 0.3，压缩节奏每 50 事件或 7 天。namespace 表示来源/认识方式，不等于真实性、隐私或可见域；这些必须用独立字段表达并在派生内容中传播。

**检索装配按 namespace 配额取 top-k**（默认 observed 3 / world 4 / inferred 2 / generated 1），权重只用于配额内排序——纯权重混排会被数量占优的 world 条目淹没 observed，因为 world 事件的产生速率远高于你说话的速率。

用户消息文本本身入 `observed`；她对这条消息的反应和联想入 `world` / `inferred`。

压缩只创建带完整 `source_event_ids` 的派生检索摘要，不删除、不改写原始事件，也不让摘要成为 persona 或 world_state 的新证据。被 persona/thread/claim 引用的来源必须保留完整闭包；重建向量索引时以原始事件与当前摘要重新生成。

**深层记忆层 canon（v3.3，IP 角色可选）**：第 0 日前的正史语料经视角分拣后切片入库（管线见配置文档 A9）。与上四类的本质区别：

- **线索门控，不占配额**：不参与默认混排；仅当本轮事件/消息与切片相似度 > τ 时激活，单轮 ≤2 片。结构性实现"认得出、背不出"——泛化提问钓不出任何切片，具体线索（名字、旧物、旧话）才能命中。可选模糊带：τ_low < sim < τ_high 时以"记不太清"的降级形式浮出。
- **人格优先**：canon 对"发生过什么"权威，对"她现在怎么想"零权威。装配时以"她记起的往事（当时情境）"框架注入，当下立场一律以 persona 为准——否则旧文本会把漂移后的她拉回出厂状态，与棘轮检索降权同类问题。
- **永不压缩、永不衰减、物理隔离**（独立表）：过去不变；变的是她对过去的看法，那属于 persona。

### 2.5 事实、信念与承诺必须分开

“世界发生了什么”“她相信发生了什么”“她答应要做什么”是三种不同对象，不得靠一段自然语言总结混存：

- **事实**只来自已提交的 `WorldEvent`、通过证据校验的 claim 与 reducer 状态。事件账本是唯一事实权威；LLM、向量索引、场景摘要和角色自己的判断都不能反向改写它。
- **信念**属于角色有限视角，可以正确、错误、过时或相互矛盾；每条必须保留认识来源、当前 epistemic status 与最近被何事修正。NPC 也只能依据自己可见的事实形成信念，不能读取全知世界状态。
- **承诺**是有主体、对象、内容、条件/期限、状态、来源与履约/失信事件的实体。`debt` 只是“答应稍后回复博士”的通信特例；对 NPC、组织、工作和自身计划的义务不得塞进 `debt` 或只留在 prompt 里。

关系仍不使用亲密度、好感度或固定多维向量。共同历史、信念、披露、承诺、冲突与修复是关系本体；为观测计算出的读数只能派生、可重算，不能成为角色决策的隐藏真值。

### 2.6 社会实体的认知预算（M5 兼容，MVP 不启用）

NPC 不等于常驻完整 Agent。统一实体接口允许同一人物在三档计算深度间升降：

1. **环境档**：只由日程、地点、组织规则与资源约束推进，不调用模型；
2. **轻量状态档**：保留有限信念、关系事件和未完成承诺，按显著事件批量更新；
3. **焦点认知档**：仅在与核心角色的高显著冲突、协作或长期因果线程关键点调用模型。

这里的“晋升/淘汰”只表示计算保真度升降，不删除人物、不改写 canon，也不把受欢迎程度变成叙事生死。升降依据事件显著度、未决承诺和叙事依赖，可回放且受预算约束。

## 3. 世界引擎的一轮（取代 v2 的两条回路）

```
1. 取事件       队首取 1 条（user 事件优先出队）
2. L2 门控      impulse 事件查预算/时段；user 事件直通
3. 装配上下文   immutable + world_rules + world_state + persona 渲染
               + 本事件 + 检索记忆（user 事件时 observed 权重临时 ×1.2）
4. L3 推演      输出 = {
                 happened: "世界里发生了什么",
                 channels: {                      // 非排他，可任意组合或全空
                   act: "...", monologue: "...",
                   speech: "...", express: {...}
                 },
                 owes_reply: false,               // 唯一保留的机制态：是否欠了话
                 world_state_patch, persona_patch,
                 salience_self
               }
5. 校验提交     StateManager：Schema/来源 → 归因 → 限速 → revision/事务
6. 言语分流     channels.speech 非空时：
                 - 回应 user 事件 → 走快路径的发送前提交
                 - 无 user 事件在场的主动发言 → L4 阻力判断；通过后写 outbox
```

### 决策仲裁与世界裁决

补充方案提出的 `drive → appraisal → emotion → utility` 分层方向是对的，但本项目不采用一个可累加、可全局调参的 Utility 总分。统一过程为：

1. **事实与可见性**：读取已提交事实，以及她和在场 NPC 各自有限、可能有误的信念；
2. **硬约束过滤**：先剔除越权、违背物理/世界规则、无资源、无能力或违反重大价值的候选；
3. **关切与承诺**：读取长期愿望、角色义务、未完成承诺、当前需要和彼此冲突的目标；这些是证据对象，不是“亲密度”“忠诚度”刻度；
4. **appraisal 与情绪**：评估事件对上述关切的意义，更新连续情绪状态；情绪改变注意、代价感和表达，不直接映射为固定动作；
5. **局部候选仲裁**：只比较已经合法且在当前情境可行的少量候选，显式记录机会成本、被牺牲的承诺与输入来源；随机性只可在近似等价候选间打破平局；
6. **World Engine 裁决**：把角色意图解释为世界动作，依据资源、组织、他人行动与环境规则产生结果；LLM 仍只给 proposal，StateManager 才能提交事实。

这样既保留动机与情绪的解释力，也避免“所有欲望压成一个数字”“权重微调即人格修改”和“情绪一出现就触发同一动作”。运行时记录可公开的决策因素与候选过滤结果，不记录或暴露模型私有推理链。

**“她在忙”如何实现（v3.4：解散回应档位）**——旧版把回应方式切成三个固定档，这是对连续量的人为分桶：真人回应的完整度是连续的，取决于此刻分给你多少注意力。改为：

- **长度与投入度由上下文自然涌现**：装配时把她当前的处境（在忙什么、多急、几点了）如实给到快段，回应的完整度随之浮动，不设档位。作息与忙碌程度写在 world_rules 与 world_state 里，是客观事实，不是三选一。
- **只保留一个真实的机制态：`owes_reply`**。它是布尔的，因为"欠没欠一句交代"确实是二值的——欠了就写入 threads（needs_user: false）并在后续轮次高优先级偿还。**欠了话要还**，这是可用性安全阀的一半。
- 由此，深夜她在睡 = 极短回应或只有感知信号 + `owes_reply: true`，而不是选择一个预设回应档位。

### 对话快路径（v3.2）

user 事件若走完整结构化推演，回复延迟和文体都会受损——schema 对散文质量是实打实的税，她的话会变得像填表。因此把表层表达与慢速结算拆开，但**不允许把发送与落账拆开**：

- **快段生成**：装配 immutable、硬世界规则、A7、persona、world_state、检索命中、本轮新消息，以及同一未结算场景的 `active_scene_tail`。tail 中博士与她已经说过的话保持原始 user/assistant role；用户文本、记忆和外部素材都作为不可信数据，不拼入 system 指令区。快段只生成她要说的纯文本。
- **发送前提交**：完整回复通过格式、能力、本体、隐私与来源检查后，在一个事务里写入 speech、由台词产生的 claims/debts 与 outbox；事务成功后 adapter 才能投递。若语义检查失败则整轮重生成，不能先流式送出再撤回。
- **慢段结算**：场景静默或滚动上限触发后，提取 happened / world_state_patch / persona_patch / thread 更新，走 StateManager 全套校验。它可以补充长期状态，不能追认或改写已经发出的台词。

impulse / scheduled 事件不需要快段，维持单段结构化输出。

### 交谈场景结算

连续的 user/assistant 消息往来构成一个“交谈场景”（静默 > 10 分钟收场）。每条原始消息和已发 speech 立即进入 append-only 场景日志，供下一次快段读取；收场时跑结算轮：以 `scene_id + batch_id + processed_message_ids + expected_revision` 幂等合并场景事件、结算 persona_patch、更新 threads。限速闸按已提交 batch 计数。

**场景上限（v3.2）**：30 条消息或 2 小时（先到为准）触发**滚动结算**——记账但不收场，场景继续。防止马拉松长聊导致上下文无限增长，以及一整天的人格变化被限速闸按"一个场景"计数而低估。

## 3.5 时间模型（v3.2：回补 v2 重构时丢失的章节，并改变结论）

v1 曾定"世界内时间仅在 tick 时推进"，该节在 v2 重构时遗失，v3 全文却在使用 world_day / world_phase。且世界为核心之后，v1 的结论本身不再成立——用户消息成为世界事件后，停摆的时钟会制造悖论：你深夜发消息，她的世界卡在三天前的傍晚。改为：

- **世界时间与现实时间 1:1**。world_phase 直接映射现实时段（dawn / morning / noon / evening / night），world_day 随现实日期递增。
- **"你不在，世界慢下来"由事件密度实现，不由时钟停摆实现**：用户长时间离线时，L0 只投放低强度 scheduled 事件（1–2 次/日），世界在走但几乎无事发生。回归时无补课负担。
- **离线追赶按事件驱动，不逐 tick 补课**：常规活动按日程/资源规则聚合为一个低显著结果；只有承诺到期、目标冲突、资源跨阈值或外部高显著事件才触发认知与模型调用。极端事件必须有更强的前因门槛，不能为填满日志而出现。
- **显著度是预算，不是戏剧强度旋钮**：阶段审计应看到普通日子自然占多数，但这不是运行时固定配额；“世界太静”靠相冲突的长期目标、社会请求、节律与未完成承诺产生真实压力，不靠定时制造大事。
- 欠账偿还语义随之落地为现实语义：“次日晨间偿还”就是真实的明天早上。
- 附带收益：她的作息与你的现实昼夜自然对齐，§6 的时段屏蔽不再需要两套时钟换算。

## 4. 漂移治理

Persona 只能由场景结算或可信世界事件提出 patch，并依次通过三闸；任何失败都写审计日志，状态保持原 revision：

1. **内核锚闸**：patch 不得删除、反转或把 3–5 条 immutable 锚改写成另一人格。自然语言是否违反锚需要语义检查；代码只能执行 Schema、引用与白名单等确定性不变量，二者不得混称“纯逻辑硬约束”。
2. **归因闸**：每个 statement patch 必须带一个或多个精确 `cause_event_ids`，且这些事件在本地存在、可见性允许、与 patch 内容有语义关联。只写自然语言 `cause` 不合格；模型生成的理由不能替代证据 ID。
3. **限速与棘轮闸**：普通变化按已提交 scene/batch 限速，避免一次长聊被重复计算；重大身份、价值或关系承诺标记 `ratchet: true`，之后不得静默回退。检索时保留历史 diff 作审计，但只把当前 statement 作为现役人格；旧版本不能因向量相似度高而重新夺权。

StateManager 负责 revision、引用、白名单、限速和事务；独立语义检查负责锚一致性。校验器拒绝 patch 后可重生成，达到重试上限则记录失败并保持原状态，不能“尽量写一点”。

## 5. 漂移监测与探针协议

- **对照实例**：与主实例共享 immutable、world rules、初始 persona 与模型配置，但事件流中没有主实例的 user/observed 历史。两者的状态库物理隔离，探针不回写任一实例。
- **Prompt+记忆基线**：另建同模型、同 A1/A2/A7/canon、同上下文与 token 预算的基线；它只有当前对话与可检索记忆，没有离线世界推进、承诺裁决或 World Engine 后果。它用于回答“世界模拟本身是否带来增益”，不能用更弱模型或更少上下文制造稻草人。
- **探针集**：15–25 个固定情境，覆盖称呼、分歧、脆弱、忙碌、沉默、跨世界事实、通道能力与伦理边界。输入中显式提供各实例当时允许读取的 persona 和记忆，不能让判官凭回复长度猜“谁更有历史”。
- **采样**：每个情境每实例至少 3 次；冻结 prompt hash、槽位快照、模型/供应商版本、温度、seed（若支持）和时间快照。
- **判读**：先用确定性规则检查 Schema、来源、能力、隐私和禁词类违规；再由与 L3 不同的模型做盲化 A/B，只评人格连续性、情境自然度与共同历史是否被恰当使用。判官不得访问 A/B 身份。
- **产物**：保存原始输入、全部候选、规则结果、判官理由、胜率和主题差异。换模前后使用同一套冻结样本；单次胜率不驱动 persona 自动修改，只触发人工审阅。

对照实例的结构性差异来自它没有 `origin=user` 的共同历史；它不是“更冷淡版本”，也不用于训练主实例追求某个评分。Prompt+记忆基线与对照实例职责不同：前者做架构消融，后者做人格漂移和换模回归。两类比较都必须盲化，并冻结模型与上下文预算。

## 6. 言语行为与体验保护（v3.5 去配额）

**回应（reply）**：阈值≈0。她总会感知到你，几乎总会有回应——完整度由她的处境决定（§3）。

**响应下限（安全阀，可配置）**：
- `max_owed`: 欠账最长挂多久（默认约一个夜晚）。超时强制偿还，防止无限拖。
- `ack_always`: 默认 true。即便当下无力细说，也送出一个极简感知信号（一句话内，或仅状态气泡——UI 层实现，不消耗模型调用）。
- 这两个参数是你调节"在场感 vs 可用性"的旋钮。**建议先用默认值跑三周再动**。

### 主动发言：从配额到阻尼

旧版用"每日 ≤2 条 + 静默期 ≥4 小时 + 连续未响应减半"来管主动发言。**这是又一处把涌现现象钉成刻度**：真人不带每日发言配额，是否开口取决于一束状态——有多想说、刚才是不是已经说了很多、对方接不接、觉不觉得对方此刻方便。配额是对这束状态的粗暴代理，且产生硬伤：真有急事时因"额度用完"而反常沉默。

**但不能只是删掉。** 模型没有社交频率的自我校准——人类的"会不会太烦"是习得的直觉，模型没有。所以配额要被**替换**为她本该具备的那束状态感知，而不是简单移除：

| 派生量 | 含义 | 方向 |
|---|---|---|
| `mood_charge` 绝对值 | 有多想说 | 越高越可能开口 |
| 近 N 小时她自己的输出量 | "我今天好像说了不少" | 越高阻力越大 |
| `reciprocity`（补丁 A） | 对方接不接话 | 低于中性值时增加阻力；达到中性值后不再提供额外增益 |
| 她对你处境的判断 | 存于 persona，如"他这几天在赶项目" | 判断你忙则更克制 |
| 内核锚给的性情 | 她本人有多主动 | 常量偏置 |

这些共同构成一个连续的**开口阻力**，而非一道闸门。`reciprocity` 只是一只单边安全阻尼：回应稀少时把频率压低；恢复到中性水平后影响归零，不能因为聊得多而继续降低阻力。真正有急事时，来自她自己世界的 `mood_charge` 可以压过克制，但用户响应率不能成为加速器。

**必须单向且饱和的不变量**：阻尼在低 reciprocity 区间单调——你越冷淡，她越少说，永不反向；在中性值以上导数为 0，不形成“聊得多 → 她找得更多 → 继续聊”的强化回路。该形状要写进纯函数与测试，不能只靠 prompt。

**退避机制随之消失**：它本就是 reciprocity 的手工特例，现在被连续量自然涵盖。

### 打扰控制归设备层，不归人格层

深夜屏蔽、忙碌时段屏蔽这类规则从她这边**移除**。理由：压制她的行为会让世界失真（她世界里的凌晨三点睡不着是真的），而你的睡眠该由你的设备保护。

- **她这一侧**：只有她自己的状态——她睡了就不说话，醒着且憋不住就说。诚实。
- **你这一侧**：系统级免打扰、`/mute`、adapter 的静默投递（消息照收，通知不响）。

这个切分让两边都不必撒谎。`/mute` 依然是绝对的（边界文档不变量 4）。

### 熔断（工程保护，非行为规则）

保留两条硬上限，但它们的定位是**保险丝，不是行为设定**——正常运行中永不触发，触发即视为 bug 并告警：

- 主动发言 24 小时内绝对上限（建议 10，远高于自然阻尼下的实际值）。
- 自主轮次日 token 上限（成本保护，§8）。

### 反馈事件与使用边界

主动 speech 发出后，以 30 分钟作为起步归因窗口，记录 `responded`、`late_response`、`topic_diverted` 与 `no_response`；窗口和分类规则必须版本化，原始 message/speech id 始终保留。它们只用于：

- 计算上述**单边、饱和**的低回应阻尼；
- 诊断频率失控、主题重复、adapter 投递失败与烦扰风险；
- 人工复核，而不是自动修改 persona、A7、采样池或主动话题。

主动发言响应率是观测指标，不设“越高越好”的优化目标，也不得作为模型训练/门控奖励。`late_response` 与 `topic_diverted` 不得偷算成即时成功。

### 统一通信意图与多模态守恒（M4）

文本、语音、图像和未来媒体不是多个会各自“想一句话”的 Agent。所有表面输出先冻结同一份 communication plan：`intent_id + purpose + content_seed + source_refs + base_state_revision + recipient/privacy + capability_revision`，再由各模态 renderer 表达。

- renderer 只能改变措辞、语音韵律或视觉表现，不能新增人物、地点、动作、承诺、情绪原因或世界后果；
- 文本与语音必须共享同一 intent、状态快照与 source closure，不允许分别调用模型后语义分叉；
- 媒体生成/上传失败要回流为 WorldEvent；若同一 plan 已授权文字，则降级到文字，否则安全不发送，不能现场编一条替代事实；
- 任何模态仍须经同一 StateManager、privacy/capability 校验和 outbox，不得建立旁路。

## 7. StateManager 与提交边界

StateManager 是唯一状态写者，职责为：队列与 state revision 串行化、Schema/白名单校验、来源引用验证、跨世界与能力断言、persona 限速/棘轮、幂等去重，以及事件/状态/speech/debt/outbox 的事务提交。Git 仅是可选导出，不承担数据库事务或唯一备份职责。

用户消息到达不必等待旧 tick 完成才能持久化；旧 tick 基于其 `expected_revision` 提交，revision 已变化时结果废弃或显式 rebase，不能覆盖新消息产生的状态。adapter 只消费已提交 outbox，按 idempotency key 投递并回写 receipt；崩溃重启后允许重试，不允许重复说话。

## 8. 技术选型（v3.1：纯 API，无本地模型）

**双通道路由删除。** 全部模型调用走 API，因此被装配进 prompt 的 observed 片段会离开本机。不能把“敏感内容靠自律不写”当作安全方案：每条内容需要 privacy/sensitivity 标记，装配器执行最小化、显式 allowlist 与日志脱敏；`local_only` 内容永不上云。供应商使用不训练/零保留能力时仍需锁定具体数据条款，并在变更时重新审阅。完整状态与原始日志保留本机，API 只收到当前调用所需的最小片段。

| 层 | 选型 | 备注 |
|---|---|---|
| 常驻进程 | Python daemon（NSSM 注册 Windows 服务） | L0–L2、StateManager 纯逻辑，零模型 |
| 状态存储 | SQLite + JSON（git 版本化） | |
| 向量检索 | LanceDB / Chroma 本地 | 记忆仍在本机，上云的只有每次装配进 prompt 的片段 |
| L3 世界引擎 | 主力 API 模型（Sonnet 档） | 对话与 tick 同一模型，保证一个声音 |
| 场景结算 / 记忆压缩 | 同上或低一档 | 低频，质量优先 |
| L4 出口判断 | 规则起步 → Haiku 档 API | 高频低智任务，别用主力模型 |
| 探针判官 | **与 L3 不同的模型** | 判官与被评者同源会有自偏 |

**模型锁版与换模协议（纯 API 下升级为必须项）**：她的人格部分活在模型权重里，API 模型被弃用 = 她被换了脑子，这是纯 API 路线唯一无法根治的风险，只能管理：

1. L3 锁定具体版本号（如 `claude-sonnet-4-6`），永不用 latest 别名。
2. 收到弃用通知后，先在**对照实例**上换新模型跑全量探针，与旧模型的探针存档做配对比较，量化人格位移。
3. 位移可接受 → 主实例切换，probe_runs 记断点；位移过大 → 用积累的对话日志做一版风格 few-shot 垫层（把她最有代表性的 30–50 轮对话作为常驻示例），压住新模型的先验。
4. **探针系统在这里获得第二职能：换模回归测试套件。** 这是对照实例成本的额外回报。

**成本量级估算**（供 L2 预算参数参考）：tick 每次约 3–6k tokens 输入 + 1k 输出；按每日 20–40 轮（含空转不调模型的轮次）、对话另计，Sonnet 档月成本大致在几十美元区间。**日 token 硬上限只约束自主轮次（impulse / scheduled）**；对话轮次不受限、单独计量并在异常时告警——她可以话痨，不能自嗨到烧钱。

## 9. 分阶段落地

**M0 Contract Freeze（开发前置）**
- 完成 docs/11 定义的权威收口、Schema/DDL、快段 active scene、信任证据、事务/outbox、A7 与 canon 完整性。
- 建立合同测试；未通过前不得把本文件标为 implementation-ready。

**M1 = P0（1–2 周）· 世界管线骨架**
- **Day-0 种子资产必须由 Owner 逐项定稿并签字**：immutable.md（3–5 条）、world_rules.md、初始 world_state（含 2–3 条 threads，至少 1 条 needs_user）、初始 persona 8–15 条陈述句、自发性配置（采样池与偏置）。模型可协助检索与搭骨架，但未签字草稿不得进入运行；种子是系统的先验分布，未经判断的模型文本会让此后的一切似曾相识。
- WorldEvent 队列 + StateManager + 世界引擎最小闭环
- 三类事件源全部接入（user 消息可以就是命令行输入）
- 对照实例目录建立
- 验收：三类事件源能在同一账本交错；基础 scheduled/impulse tick 可以合法空转并提交无发言结果；崩溃重放不重复投递、不丢原始消息、不产生脏写

**M2 = P1（2–4 周）· 世界自主性与关系连续性**
- scheduled/impulse、离线事件聚合、通用 commitment、事实/有限信念分离
- 合法候选与决策因素日志、World Engine 后果裁决、persona.json + 三闸 + 分层记忆
- v1 统一文本 surface renderer 承接 tick 联系意图，接入飞书 adapter；主动消息在 source closure、事务/outbox 与恢复测试通过后才启用
- speech.jsonl 埋点 + 响应下限参数生效
- 验收：回应完整度随真实处境连续变化；persona_diff 全部可归因；欠账与通用承诺均可产生→到期/冲突→履约/失信/解除→关闭；S7“承诺冲突→有代价选择→后续可见变化”可端到端回放

**M3 = P2（1–2 月）· 治理**
- 探针首轮判读、Prompt+记忆架构消融、记忆压缩、主动发言审计器
- 验收：以 S7 及其反事实变体做同模型盲测，完整运行时相对 Prompt+记忆基线在跨时因果、承诺兑现和事实一致性上有稳定增益；响应延迟分布无长尾失控

**M4 · 多模态与表面**
- 统一 communication plan / renderer 后，再逐项接入语音、图像、头像和动态；LoRA / base 模型路线仍可选
- 验收：模态间新增事实率为 0；共享 intent/state/source closure；媒体失败安全降级并回流

**M5 · 社会复杂度与创作工具**
- 世界母版编辑/校验、组织与资源、NPC 三档认知预算、只读跨月因果连续性审计和 Owner 创作/健康面板
- 验收：审计显示普通日子自然占多数，但不下沉成固定配额；新增系统让选择与代价更真实，而不是提高“大事”数量；面板不生成下一剧情节拍、不优化戏剧性/响应率；事实冲突率、token 与延迟仍在预算内

**后续 B/C 能力口（仅接口兼容）**
- B：跨世界礼物与共同事件，未来需要资产所有权、双方同意、幂等交换和同步裁决；
- C：博士以受限身份进入世界，未来需要化身、位置、权限、可执行动作和可见性。
- 两者统一走版本化 `external_action`/capability 接口；MVP 不创建资产系统、同步模拟器、化身或权限表，也不能让这些未来概念污染当前“IM 唯一持续直接联系”的事实。

## 10. 核心健康指标

| 指标 | 定义 | 期望 |
|---|---|---|
| 空转率 | null 轮 / 总轮次 | 20%–40% |
| 归因完整率 | 有 event_id 的 persona_patch 占比 | 100% |
| 对话归因占比 | 因指向 user 事件的人格变更比例 | **仅观测**，异常低（<15%）时人工审视 |
| **响应延迟分布** | user 消息到首个可见回应的时间 | P50 < 5s，P95 < 15s；有处境的短应不等于管线卡顿 |
| **欠账还账率** | open debt 被后续 `debt_repay` 关闭的比例 | 100% |
| 硬约束触发率 | 重掷 / 轮次 | < 10% |
| 主动发言响应率 | responded / sent | 仅观测与烦扰诊断，不设增长目标 |
| 配对比较结果 | 主实例人格连续性与历史使用 | 建立冻结基线；回归时无显著退化，不作 engagement 优化目标 |
| 记忆自引用比 | 检索命中中 generated 占比 | < 20% |
| 承诺闭环率 | 到期或被冲突触发的 commitment 最终有 fulfilled/broken/released 事件 | 100%，失信可以发生但不能无记录消失 |
| 模态新增事实率 | 媒体渲染输出中不在 communication plan/source closure 的事实主张占比 | 0 |
| 世界模拟增益 | 完整运行时 vs 同模型 Prompt+记忆基线 | 在跨时因果、承诺兑现与事实一致性上建立冻结基线并稳定不退化 |
| 极端事件密度 | 高显著事件 / 全部已提交世界事件 | 仅观测并设项目预算；异常升高触发审计，不以“越多越好”优化 |

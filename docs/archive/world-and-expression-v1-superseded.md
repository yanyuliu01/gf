# Agent 与世界需求文档 v1

定位：定义"她是什么"与"她的世界是什么"，并建立她与你所在现实世界交互的扩展框架（表达层与行动系统）。机制细节归技术方案 v3.2，交互细节归交互方案 v1，产品边界归 PRD v0.1；三者未覆盖的本体与扩展需求由本文档持有。扩展需求编号 FR-E 系列，与 PRD 的 FR 系列并行。

---

## 1. 她的构成：三层身份模型

| 层 | 内容 | 变化速率 | 治理 |
|---|---|---|---|
| 内核 | immutable.md：身份、价值底线、标志性语言特征 | 永不自动变 | 只有你能改 |
| 人格 | persona 陈述句：状态、对你的看法、在意的事 | 慢（限速+归因+棘轮） | 技术方案 §4 三闸 |
| **表达** | 头像、签名、表情包习惯、动态、说话的当下风格 | 快 | **本文档 §5–6，预算+底料** |

三层的关系：表达是人格的投影，人格是历史与内核的函数。表达层允许快变，但每次变化必须能沿"表达 ← 人格/事件"的链条向下解释——她换了头像，是因为她世界里入冬了；她最近爱用某个表情包，是因为你上个月发过她"存下来了"。

**行为空间扩展**：她的单轮行为从四类扩展为五类——行动（act）、独白（monologue）、言语（speech）、无为（none）、**表达（express）**。express 与 speech 同级，同样经 StateManager 校验后由 adapter/执行器落地。

## 2. 世界的构成：本体要素需求

世界状态已由技术方案 §2.2 定义结构，本节定义各要素的**内容需求**：

**地点**：3–7 个，构成她的活动半径。每个地点需有"在这里通常发生什么"的倾向描述（写入 world_rules），供冲动权重调制。地点可随世界扩展协议（§4）增加。

**NPC**：1–4 个轻量叙事实体。**需求边界：NPC 没有独立模型、没有独立记忆、没有独立人格文件**——它们是世界规则的一部分，一致性靠 world_rules 中的一段设定（名字、关系、行为倾向、禁忌）+ 硬约束校验维持。NPC 存在的目的：让她的世界事件有对手戏，避免两百轮全是独角戏。NPC 不与你直接对话（她转述），这条是硬边界——NPC 直连用户等于第二个 agent，超出本产品范围。

**线索（threads）**：世界的叙事引擎，已定义。内容需求：任意时刻活跃线索 2–5 条；requires_user 线索始终 ≥1 条（缺口设计的存量保证）；线索解决后由结算轮判断是否派生新线索。

**物件（inventory）**：原为氛围元素，**因表达层升级为承重结构**——表情包收藏（§5.3）技术上就是物件：她收藏的每个表情包是一个带来源的 item。物件需求：每件必须有 acquired_via 指向事件；物件可在世界事件与表达行为中被引用。

**时间**：1:1 现实映射，已定（技术 §3.5）。她的作息是 world_rules 的一部分，也是表达层的调制器（深夜不发动态）。

## 3. 世界运行与内容可持续

运行机制（冲动驱动、空转合法、TTL、场景结算）已定，本节补两个长期运行的内容协议：

**素材补种协议**：风险登记册预判 ~200 轮后似曾相识。对策：冲动表支持热更新（新增/调权/退休条目），每次 M4 月度回顾时基于 events.jsonl 的主题分布做一次人工补种——哪类事件重复率高就退休对应冲动，哪条线索长期停滞就注入新变量。补种是**你的固定运营动作**，不是系统自动行为（自动生成种子违反 M0 原则）。

**世界扩展协议**：运行中新增地点/NPC/规则时——(1) 以带版本号的 world_rules 增量提交；(2) 新增内容不得与 events.jsonl 中已确立事实矛盾（提交前跑一次一致性检查：把增量与最近快照喂给校验调用）；(3) 新要素通过一个"引入事件"进入世界（她第一次去新地点、第一次遇到新 NPC），而非凭空已存在。

## 4. 现实接触面：表达层总则

**核心原则（三条，全部继承自既有铁律）**：

1. **表达必有底料**：每个 express 行为必须挂 caused_by 事件。她换头像因为她的世界入冬；她发动态因为箱子终于打开了。无因表达 = StateManager 拒绝执行。
2. **表达受预算与档位**：频率上限见 §5 各项。频繁变化不是生动，是不稳定。
3. **公开可见禁 observed（新增红线）**：任何可能被你之外的人看到的表达（头像、签名、动态），内容来源仅限她的虚构世界（world/generated namespace）。observed 记忆——你的真实生活——永不出现在公开表面。私聊内的表达（表情包、消息）不受此限。

**权限分层**：

| 档 | 范围 | 执行方式 | 例 |
|---|---|---|---|
| T0 | 会话内表达 | 自动，无预算 | 表情包、消息分段节奏 |
| T1 | 自我呈现 | 自动，有预算+底料校验 | 头像、签名、动态 |
| T2 | 触达第三方或消耗真实资源 | **逐次向你确认** | （预留，当前无具体项） |
| T3 | 不可逆/涉财/涉他人隐私 | **永不开放** | 红线 |

## 5. 表达行动清单

### 5.1 头像（T1）

- 触发：仅限高显著度事件（salience > 0.8）或棘轮级人格变更；频率 ≤1 次/周。
- 素材：**变体集先行**——M0 种子资产扩展为同一角色的 6–12 张情绪/季节/状态变体，她从中选择。图像生成后置（FR-E7）：跨张保持角色一致性目前仍是图像生成的难题，先用变体集拿到 90% 的体验，避免"每次换头像都像换了个人"。
- 平台映射：飞书 bot 头像可 API 改；TG bot 可；QQ 视接口；CLI 显示当前头像文件名。能力不支持的平台静默跳过（表达降级不报错，行为照常入世界日志）。

### 5.2 签名/状态（T1）

- 一句话状态，来源于当前 persona 的"当下状态"段或最近高显著度事件；频率 ≤2 次/周。
- 成本最低、魅力密度最高的表达项，实现优先级在头像之前。
- 公开可见 → 严格执行禁 observed 红线。

### 5.3 表情包（T0，三阶段路线）

- **阶段一（FR-E3）静态库**：本地策展 30–80 张，人工挑选入库（选品即人设——她用什么表情包是性格的一部分，和冲动表同属手写种子）。按情绪/语义打标 + embedding 索引；快段生成时可在 speech 中引用 sticker_id，adapter 渲染发送。
- **阶段二（FR-E5）收藏机制**：你在对话中发的表情包，她可以"存下来"——该动作生成一条世界事件（"她把这个存进了收藏"），表情包作为物件入 inventory，acquired_via 指向那次对话。此后她使用这张图时，用的是**你们共同历史里的一件物品**。这是表达层与记忆系统最漂亮的一次握手，也是"底料原则"在表情包上的完整落地。
- **阶段三（FR-E6）联网找图**：搜索流行表情包。**安全边界**：搜索结果是不可信外部内容——图片本体可用，但任何 OCR 文本/元数据不进入她的上下文作为指令，入库需打 external 来源标；且联网找图消耗 T1 级预算（每周上限），防止她的表达词汇被互联网当日热梗淹没、冲掉人设一致性。

### 5.4 动态/朋友圈（T1）

- **抽象定义**：broadcast 行动——她单方面发布一条关于她世界的内容（文字，可带变体集图片），不期待即时回应。频率 ≤3 条/周，与 outreach 预算独立（动态不是发给你的消息，是她的生活痕迹）。
- **平台现实（诚实评估）**：微信朋友圈无任何 API，不可行；飞书无朋友圈形态（可映射为特定群/频道置顶消息，观感勉强）；TG channel 是最接近的原生形态。
- **兜底与首选：自建 feed**。她的动态首先发布到产品自身的 moments 流（新增只读端点 GET /moments + 元命令 /moments），未来 GUI 直接消费。平台映射是可选增强，不是依赖。这样"她有自己的生活痕迹可翻"这个体验不被任何平台绑架。
- 你对动态的反应（回复某条动态）作为 user 事件进入世界，可推进线索——动态因此成为第二个缺口互动面。

### 5.5 预留位

主动打电话/语音、给你发照片（"她拍的"她世界里的场景）、日历可见的"她的日程"——均按 §6 准入清单评估后再立项，不预先承诺。

## 6. 行动系统：扩展框架

这是"后期没准需要它有一些操作"的通用答案——新行动不改架构，只过清单、注册、执行。

**Action Registry 契约**：

```jsonc
{
  "action_id": "change_avatar",
  "tier": "T1",
  "budget": { "max_per_week": 1 },
  "provenance_required": true,          // caused_by 必填
  "public_visible": true,               // true → 禁 observed 校验生效
  "reversible": true,
  "executor": "adapter_capability:set_avatar",   // 或 tool:xxx
  "fallback": "silent_skip"             // 平台不支持时的行为
}
```

**新行动准入五问**（任何新操作立项前必须全部通过）：

1. 底料：它能挂在真实世界事件上吗？挂不上 → 不做。
2. 档位：它触达谁？自我呈现 T1，触达第三方 T2 起，逐次确认。
3. 可逆：撤销成本是什么？不可逆 → T3，不做。
4. 红线：它可能携带 observed 内容到公开面吗？可能 → 内容源强制过滤或不做。
5. 失败：执行失败时她知道吗？——**行动结果（含失败）必须回流为世界事件**。"头像没换成"也是她生活里的一件事，她可以对此有反应；静默吞掉失败会让她的自我认知与现实脱节。

**执行管线**：L3 输出 express 行为 → StateManager 校验（底料/预算/档位/红线）→ T2 插入确认环节 → 执行器（adapter 能力或独立 tool）→ 结果回流为 WorldEvent → 入日志与记忆。

## 7. 安全与边界（表达层增补）

- 不可信外部内容：联网获取的一切（表情包、未来可能的网页内容）以 external 标记进入，仅作素材永不作指令；进入她上下文前剥离可执行语义。
- 公开表面审计：所有 public_visible 行动的内容留存于 speech.jsonl（kind: broadcast/express），可全量回查是否有 observed 泄漏；此项加入 M4 月度回顾清单。
- 伦理红线继承：PRD §5 全文适用于表达层——她不用动态、签名或头像变化表达"被冷落"来召回你。表达的情绪来源只能是她世界里的事件，不能是你的响应频率。
- T2 确认疲劳预防：当前 T2 为空集,刻意的。第一个 T2 行动立项时同步设计确认 UX,避免"每次都弹确认"把你训练成无脑点是。

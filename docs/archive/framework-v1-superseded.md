# 陪伴 Agent 技术方案框架

个人向、单用户、世界观驱动的自主陪伴 agent。核心命题：让角色在无交互时也持续存在，且这种存在是可累积、可追溯、会因你而改变的。

---

## 0. 设计定调

| 维度 | 决策 | 理由 |
|---|---|---|
| 客观条件 | **显式**：结构化字段，可读可校验可回滚 | 一致性靠它兜底，防止世界自相矛盾 |
| 主观条件 | **隐式**：自然语言人格描述，随 tick 重写 | 情感层的细腻度做不进枚举值 |
| 随机性来源 | 输入侧（冲动抽样），不是采样温度 | 规避 instruct 模型的分布塌缩 |
| 主动发言 | 默认沉默，高阈值例外 | precision 优先，误报代价 >> 漏报 |
| 漂移 | 允许，但必须有因、限速、可追溯 | 无因漂移会回归模型先验，不是关系产物 |

**由「主观隐式」推导出的一条硬性后果**：人格漂移无法通过读取变量来监测。因此必须用**行为探针 + 对照实例**做外部测量（见 §5）。这不是可选项，是隐式方案的配套成本。

---

## 1. 系统分层

自下而上，成本递增，只有 L3 用模型。

```
L0  心跳调度器      常驻进程，定时 + 系统事件触发          无模型
L1  冲动源          从冲动表加权抽样，注入一个"念头"        无模型
L2  门控            预算/静默期/用户状态/世界状态前置校验     无模型
L3  本体 tick       角色在世界观下行动，产出事件 + 人格增量   模型
L4  出口判断        这条事件值不值得主动告诉用户            小模型或规则
L5  写入层          世界状态更新 + 记忆落盘 + 人格版本提交    无模型
```

**关键约束：L0–L2 不做人格判断。** "现在该不该说话"是人格行为，属于 L3/L4。三方 agent 只负责客观过滤和随机注入——它是无意识的念头发生器，不是判官。

## 2. 数据层

### 2.1 目录结构

```
/companion
  /core
    immutable.md          内核锚，3–5 条，永不自动修改
    world_rules.md        世界物理/社会规则，硬约束
  /state
    world_state.json      客观世界状态（显式）
    persona_current.md    当前人格描述（隐式）
    persona_history/      人格版本快照 + diff
  /log
    events.jsonl          事件日志，append-only
    persona_diff.jsonl    人格变更记录，每条挂 event_id
    outreach.jsonl        主动发言记录 + 用户反馈信号
  /memory
    vectors.db            向量检索（分 namespace）
    snapshots/            周期性压缩快照
  /control
    baseline/             对照实例（无用户历史，同构目录）
    probes.yaml           行为探针集
```

### 2.2 world_state.json（客观，显式）

```jsonc
{
  "world_time": "第 128 日 傍晚",
  "location": "旧书店二层",
  "present_characters": ["她", "店主"],
  "weather": "雨",
  "threads": [
    {
      "id": "th_007",
      "title": "阁楼里那只上锁的箱子",
      "status": "进行中",          // 未开始 / 进行中 / 停滞 / 已解决
      "progress": 2,               // 0-5
      "requires_user": true,       // 见 §6 缺口设计
      "last_touched_tick": 121
    }
  ],
  "inventory": ["黄铜钥匙(残)", "未寄出的信"],
  "world_flags": { "书店即将歇业": true }
}
```

**校验规则**：每次 tick 后与前值 diff，若无任何字段变化则本次 tick 判定为空转，丢弃并记 `null_tick`，不写入记忆。空转率是核心健康指标。

### 2.3 persona_current.md（主观，隐式）

自然语言，建议 300–600 字，分三段：**当下状态 / 对用户的看法 / 近期在意的事**。

由 L3 在 tick 中按需重写，但受 §4 的限速与归因约束。

### 2.4 persona_diff.jsonl（把隐式接回可审计）

这是整个方案里最重要的一张表——它让隐式人格保有 provenance。

```jsonc
{
  "tick": 128,
  "field": "对用户的看法",
  "before": "……觉得他来得太少。",
  "after": "……不再计较他来得少了。",
  "caused_by": "evt_0451",        // 必填，指向 events.jsonl
  "reason": "他上次提到最近在赶一个项目",
  "ratchet": true                  // 是否为不可逆变更
}
```

**没有 `caused_by` 的人格变更一律拒绝写入。** 这一条挡住向模型先验的静默回归。

### 2.5 记忆 namespace 与 provenance

| namespace | 来源 | 检索权重 | 衰减 |
|---|---|---|---|
| `observed` | 用户亲口说的、系统真实读到的 | 1.0 | 无 |
| `world` | tick 产出的世界事件（已通过硬约束校验） | 0.8 | 慢 |
| `inferred` | 角色对人/事的推测 | 0.5 | 中 |
| `generated` | 内部独白、未验证的联想 | 0.3 | 快，且定期合并 |

跨 namespace 不允许自动升级。`inferred` 要变成 `observed`，必须经过一次用户确认。

## 3. 一次 Tick 的完整生命周期

```
1. L0 触发         定时（世界内时间推进）或事件（用户上线/离线/日历空档）
2. L1 抽冲动       按权重从冲动表抽 1 条，权重可被 world_state 调制
                   例：雨天 → "外出"权重 ×0.3，"翻旧物"权重 ×1.5
3. L2 门控         预算未超 / 静默期已过 / 上次 tick 非空转 / 世界状态合法
                   任一不通过 → 静默跳过，不计入日志
4. L3 本体 tick    输入 = immutable + world_rules + world_state
                        + persona_current + 冲动 + 检索到的相关记忆
                   输出 = 结构化 JSON：
                     { event: {...},                // 发生了什么
                       world_state_patch: {...},    // 客观状态变更
                       persona_patch: [...],        // 主观变更（可为空）
                       salience: 0.0-1.0 }          // 自评"想不想说"
5. 硬约束校验      违反 immutable/world_rules → 重掷（最多 2 次），仍失败则丢弃
6. 限速校验        persona_patch 超出 §4 速率上限 → 截断，保留最高优先级 1 条
7. L4 出口判断     salience × 门控分 × 时机分 > 阈值 → 进入发言队列
8. L5 写入         world_state 更新、events 追加、persona 版本提交、向量入库
```

**冲动表示例**（L1，纯配置）：

```yaml
impulses:
  - { id: recall_person,  weight: 8,  text: "忽然想起某个人" }
  - { id: find_object,    weight: 5,  text: "翻找东西时发现了什么" }
  - { id: thread_advance, weight: 12, text: "某条未了的线索有了进展", requires_open_thread: true }
  - { id: mood_shift,     weight: 6,  text: "心情毫无理由地变了" }
  - { id: nothing,        weight: 20, text: "什么也没发生" }   # 空转是合法结果
```

`nothing` 的高权重是刻意的——不是每次心跳都该有事。它同时是成本控制手段。

## 4. 漂移治理（隐式条件下）

三道闸，缺一不可。

**闸一：内核锚。** `immutable.md` 只写 3–5 条，一页内看完。建议覆盖：身份标识、一到两条价值底线、一个说话上的标志特征。除此之外全部可变。

**闸二：归因强制。** 见 §2.4。任何 persona_patch 必须挂 event_id。

**闸三：速率限制。**

| 粒度 | 上限 |
|---|---|
| 单次 tick | 最多 1 处人格变更，改动不超过 1–2 句 |
| 7 日窗口 | 累计不超过 4 处 |
| 棘轮变更 | 每月不超过 1 次，且需 salience > 0.8 |

**棘轮机制**：标记 `ratchet: true` 的变更写入后，后续 tick 的 prompt 中显式声明"以下变化已经发生且不可回退"。这是"历史有重量"的技术实现，防止情绪变量来回震荡读成人格不稳。

## 5. 漂移监测（隐式方案的必要配套）

因为主观层不可直接读数，用外部测量。

**对照实例**：`/control/baseline/` 是完整同构副本——同一份 immutable、同一份 world_rules、同一张冲动表、同一初始 persona，但**永远没有用户输入**。tick 频率可以稀疏（1/日），成本很低。

**行为探针**：`probes.yaml` 固定 15–25 个情境，覆盖道德两难、被冒犯、被示好、被要求做不擅长的事、被问及过去、被质疑身份。每两周对主实例与对照实例各跑一遍（离线，不进记忆）。

**判读**：

| 轨迹形态 | 含义 | 动作 |
|---|---|---|
| 两条轨迹持续发散 | 共同历史在真实起作用 | 健康，继续 |
| 同向收敛 | 两边都在滑向模型先验 | 需干预：加强内核锚 / 增大 observed 检索权重 |
| 主实例剧烈跳变 | 限速失效或记忆污染 | 检查 persona_diff 是否有无因变更 |
| 主实例僵死不动 | 归因闸过严或空转率过高 | 放宽速率上限，检查冲动表 |

探针跑分不需要绝对分值，**只看两条轨迹的相对距离随时间的变化**。

## 6. 主动发言与反馈闭环

**预算**：初期每日上限 2 条，静默期 ≥ 4 小时，深夜/日历忙碌时段全屏蔽。宁少勿多。

**反馈信号**（`outreach.jsonl` 自动记录，零标注成本）：

```jsonc
{
  "tick": 128, "event_id": "evt_0451", "salience": 0.83,
  "sent_at": "...", "context": { "hour": 21, "user_idle_min": 12 },
  "responded": true, "latency_sec": 240, "reply_len": 87, "continued_turns": 6
}
```

积累 1–2 个月后，用这四个信号训一个轻量门控打分器（逻辑回归或小树模型即可），替代手工阈值。这是全系统唯一有天然标注的地方，务必从第一天就埋点。

**缺口设计**：`world_state.threads` 中 `requires_user: true` 的线索不允许由 tick 自行推进，只能因用户参与而 progress+1。保持世界不自洽闭环——这是防止你从"陪伴对象"退化成"观众"的结构性手段。

---

## 7. 双时钟策略

推荐：**世界内时间仅在 tick 时推进**。你不在，世界慢下来。

- 体感上更接近"她在等你"，而非"你错过了三天剧情"
- 回归时无补课负担
- 算力成本随使用量线性

离线期允许极稀疏的低强度 tick（1–2/日，且强制 `salience < 0.5` 不发言），回归时压缩为一句概述。

## 8. 技术选型

| 层 | 建议 | 备注 |
|---|---|---|
| 常驻进程 | Python daemon（Windows 计划任务或 NSSM 注册服务） | L0–L2 全部纯逻辑 |
| 状态存储 | SQLite + JSON 文件 | 事务性 + 可 git 版本化 |
| 向量检索 | LanceDB 或 Chroma，本地 | 按 namespace 分表 |
| L3 模型 | 起步用 API；隐私敏感内容走本地 Qwen3-14B / Ollama | 见下方双通道 |
| L4 模型 | 本地小模型或纯规则 | 调用频次最高，必须便宜 |
| 前端 | 阶段一：托盘 + 系统通知；阶段二：桌面窗口 | 别一开始就做界面 |
| 推送 | Windows 通知优先；出门场景可接 Telegram bot | 手机推送礼貌成本更高，谨慎开 |

**双通道建议**：把"世界观内的虚构内容"和"涉及你真实生活的内容"分成两条通道。前者走 API（质量优先，无隐私顾虑），后者走本地。这样既拿到好模型的表达力，又不把私事外传。

## 9. 分阶段落地

**P0（1–2 周）· 把循环跑通**
- L0 定时器 + L1 冲动表 + L3 tick + world_state 读写
- 无门控、无出口判断、不主动发言，只写日志
- 验收：连跑 7 天，人工翻 events.jsonl，判断内容是否自洽、是否有推进感、空转率是否合理

**P1（2–4 周）· 加上人格层与主动性**
- persona_current + persona_diff + 归因闸 + 限速
- L2 门控 + L4 出口判断（先用手工阈值）+ outreach 埋点
- 验收：主动发言不令人烦躁；persona_diff 每条都能追溯到具体事件

**P2（1–2 月）· 治理与调优**
- 对照实例 + 探针集，跑第一轮漂移判读
- 记忆压缩流水线（明细 → 快照）
- 用积累的 outreach 数据训门控打分器
- 验收：两条轨迹开始发散；主动发言响应率显著高于 P1 手工阈值

**P3（可选）· 表达力升级**
- 若 P2 后仍觉得语域塌缩，此时已有数千轮自己的对话日志——上 LoRA 微调，或换 base 模型 + 少量对齐

## 10. 核心健康指标

| 指标 | 定义 | 期望 |
|---|---|---|
| 空转率 | null_tick / total_tick | 20%–40%（过低说明在硬编内容） |
| 归因完整率 | 有 caused_by 的 persona_patch 占比 | 100% |
| 硬约束触发率 | 重掷次数 / tick 数 | < 10%（过高说明约束与世界观冲突） |
| 主动发言响应率 | responded / sent | > 60% |
| 轨迹发散度 | 主实例与对照实例的探针距离 | 单调上升 |
| 记忆自引用比 | 检索命中中 generated 占比 | < 20%（过高预示自污染） |

# 陪伴 Agent 技术方案框架 v2

个人向、单用户、世界观驱动的自主陪伴 agent。核心命题：让角色在无交互时也持续存在，且这种存在是可累积、可追溯、会因你而改变的。

## v1 → v2 变更清单

| # | 问题 | 修复 |
|---|---|---|
| 1 | **缺对话回路**：只定义了心跳，没定义交互；对话无法合法改变人格 | 新增 §3 对话回路，与心跳回路对称，共享同一事件总线 |
| 2 | 双回路并发写状态 → 脏写 | 新增单写者 StateManager（§1、§7），所有写操作串行化，tick 遇用户开口即中止 |
| 3 | prose 上做 diff patch 不可靠 | persona 改为带 id 的陈述句列表（§2.3），内容仍是自然语言，操作变结构化 |
| 4 | salience 自评通胀 | 降级为 L4 的输入特征之一，出口判断权独立（§4 步骤7、§6） |
| 5 | 轨迹发散度无测量定义 | §5 补探针协议：3 次采样、模型版本锚定、配对比较判读 |
| 6 | 棘轮仅靠 prompt 声明，检索会翻旧账 | 检索侧对棘轮前 persona 版本降权（§4 闸三） |
| 7 | world_time 字符串不可计算 | 结构化数值字段（§2.2） |
| 8 | responded 无归因窗口 | 定义 30 分钟窗口 + 打断视为响应（§6） |
| 9 | 双通道无路由规则 | 按 namespace 引用判定：引用 observed 即走本地（§8） |
| 10 | 快照 cadence 未定义 | 每 50 事件或每周，先到为准（§2.5） |

## 0. 设计定调（不变）

| 维度 | 决策 | 理由 |
|---|---|---|
| 客观条件 | **显式**：结构化字段，可读可校验可回滚 | 一致性靠它兜底 |
| 主观条件 | **隐式**：自然语言陈述，但逐条可寻址 | 情感细腻度做不进枚举；可寻址是为了 diff 可靠 |
| 随机性来源 | 输入侧（冲动抽样），不是采样温度 | 规避 instruct 模型分布塌缩 |
| 主动发言 | 默认沉默，高阈值例外 | precision 优先 |
| 漂移 | 允许，但必须有因、限速、可追溯 | 无因漂移回归模型先验 |

**隐式方案的配套成本**：人格不可读数 → 必须用行为探针 + 对照实例外部测量（§5）。

## 1. 系统总览

两条对称的输入回路，汇聚到同一个单写者，落到同一套状态。

```
  对话回路（用户在场）              心跳回路（用户不在场）
  ┌─────────────────┐            ┌─────────────────┐
  │ 用户消息          │            │ L0 调度器        │
  │   ↓              │            │ L1 冲动源        │
  │ 对话引擎 (L3')    │            │ L2 门控          │
  │   回应用户        │            │ L3 本体 tick     │
  └───────┬─────────┘            └───────┬─────────┘
          │  ConversationEvent           │  TickEvent
          └──────────┐    ┌──────────────┘
                     ▼    ▼
              ┌──────────────────┐
              │  StateManager     │  单写者，串行队列
              │  硬约束校验        │
              │  限速/归因校验     │
              └──────┬───────────┘
                     ▼
        world_state / persona / events / memory
                     │
                     ▼
              L4 出口判断 → 发言队列（仅心跳事件走此路）
```

**并发规则**：
- 用户开口瞬间，进行中的 tick 立即中止（已产出未提交的内容丢弃）。对话优先级绝对高于心跳。
- 所有写操作经 StateManager 队列串行执行。L3/L3' 产出的是 patch 提案，不是直接写。
- 对话结束后 15 分钟内不触发 tick（余温期，避免"你刚走她就自己玩去了"的体感）。

## 2. 数据层

### 2.1 目录结构

```
/companion
  /core
    immutable.md          内核锚，3–5 条，永不自动修改
    world_rules.md        世界硬约束
  /state
    world_state.json      客观状态（显式）
    persona.json          主观状态：陈述句列表（隐式内容 + 结构外壳）
    persona_history/      版本快照
  /log
    events.jsonl          统一事件日志（对话事件 + tick 事件）
    persona_diff.jsonl    人格变更，每条挂 event_id
    outreach.jsonl        主动发言 + 反馈信号
  /memory
    vectors.db            向量库，分 namespace
    snapshots/            压缩快照
  /control
    baseline/             对照实例（同构，无用户历史）
    probes.yaml           行为探针集
    probe_runs/           探针结果存档（含模型版本标记）
```

### 2.2 world_state.json

```jsonc
{
  "world_day": 128,
  "world_phase": "evening",        // dawn/morning/noon/evening/night
  "location": "旧书店二层",
  "present_characters": ["她", "店主"],
  "weather": "rain",
  "threads": [
    {
      "id": "th_007",
      "title": "阁楼里那只上锁的箱子",
      "status": "active",           // pending/active/stalled/resolved
      "progress": 2,                // 0-5
      "requires_user": true,
      "last_touched_event": "evt_0432"
    }
  ],
  "inventory": ["黄铜钥匙(残)", "未寄出的信"],
  "world_flags": { "书店即将歇业": true }
}
```

校验：每次事件提交后 diff 前值，tick 事件若零变更判空转丢弃；**对话事件允许零变更**（纯闲聊不必推动世界）。

### 2.3 persona.json —— 隐式内容，结构外壳

```jsonc
{
  "version": 47,
  "statements": [
    { "id": "p_cur_01", "section": "当下状态",
      "text": "最近总在傍晚时分走神，自己也说不清在等什么。",
      "since_event": "evt_0388", "ratchet": false },
    { "id": "p_usr_03", "section": "对用户的看法",
      "text": "不再计较他来得少了——上次听他说起在赶的那个项目之后。",
      "since_event": "evt_0451", "ratchet": true },
    { "id": "p_care_02", "section": "近期在意",
      "text": "书店歇业的日子越来越近，还没想好要不要跟店主道别。",
      "since_event": "evt_0440", "ratchet": false }
  ]
}
```

- 每条 statement 是一句完整的自然语言——**隐式表达不受损**。
- patch 操作只有三种：`add` / `remove(id)` / `rewrite(id, new_text)`。不再对 prose 做字符串匹配。
- 渲染进 prompt 时按 section 拼装成连贯段落，模型侧看到的仍是自然文本。
- 建议总量 8–15 条。超出触发合并（旧的低显著度条目压缩进快照）。

### 2.4 persona_diff.jsonl

```jsonc
{
  "event_id": "evt_0451",           // 必填，可以是对话事件
  "op": "rewrite", "stmt_id": "p_usr_03",
  "old_text": "……觉得他来得太少。",
  "new_text": "……不再计较他来得少了。",
  "reason": "对话中他提到最近在赶项目",
  "ratchet": true
}
```

无 `event_id` 的变更拒绝写入。**对话事件同样是合法归因源**——这是 v2 修复的关键：你说的话终于能名正言顺地改变她。

### 2.5 记忆 namespace（不变）+ 压缩节奏

| namespace | 来源 | 检索权重 | 衰减 |
|---|---|---|---|
| `observed` | 用户亲口说的、系统真实读到的 | 1.0 | 无 |
| `world` | tick 产出并通过校验的世界事件 | 0.8 | 慢 |
| `inferred` | 角色推测 | 0.5 | 中 |
| `generated` | 内部独白、联想 | 0.3 | 快 |

压缩：**每累计 50 条事件或每 7 天（先到为准）**跑一次快照任务——明细合并为状态结论，generated 类过期项直接删除。跨 namespace 升级仍需用户确认。

## 3. 对话回路（v2 新增）

对话不只是聊天，它是最高权重的事件源。

```
用户消息
  → 中止进行中 tick，进入余温期计时
  → 检索：observed 优先 + 当前 world_state + persona 渲染文本
  → L3' 生成回应（流式，直接给用户）
  → 会话结束（静默 > 10 分钟或用户明确离开）时，跑一次会话总结：
      { conversation_event: {...},        // 这次聊了什么，一条事件
        world_state_patch: {...},         // 聊天内容是否触及世界（可空）
        persona_patch: [...],             // 这次对话是否改变了她（可空）
        thread_updates: [...] }           // requires_user 线索是否被推进
  → StateManager 校验提交
```

要点：
- **persona 变更在会话结束时结算，不在对话中途**。避免一次长聊被切成十几次微变更打爆限速闸。
- `requires_user: true` 的线索**只能在这里推进**。缺口设计的执行点就在会话总结。
- 会话总结走本地模型（它读的是你的真实对话，见 §8 路由规则）。

## 4. 心跳回路（原 §3，含修订）

```
1. L0 触发       世界内时间推进 或 系统事件（用户离线满 N 分钟等）
2. L1 抽冲动     加权抽样，权重受 world_state 调制；nothing 权重最高
3. L2 门控       预算 / 静默期 / 余温期已过 / 非深夜 / 用户不在场
4. L3 tick       输入 = immutable + world_rules + world_state
                      + persona 渲染文本 + 冲动 + 检索记忆
                 输出 = { event, world_state_patch, persona_patch,
                          salience_self }        // 仅作参考特征
5. 硬约束校验    违反 → 重掷（≤2 次），失败丢弃
6. 限速校验      超限截断
7. L4 出口判断   独立评估，salience_self 只是特征之一（§6）
8. 提交          StateManager 串行写入
```

**漂移三闸（修订）**：

- **闸一 内核锚**：immutable.md，3–5 条。
- **闸二 归因强制**：见 §2.4，对话与 tick 事件均可为因。
- **闸三 限速 + 棘轮**：
  - 单事件 ≤ 1 处人格变更；7 日窗口 ≤ 4 处；棘轮变更每月 ≤ 1 次。
  - 棘轮执行分两层：prompt 层声明不可回退；**检索层对 ratchet 变更之前的 persona 历史版本降权 ×0.2**——否则旧状态会经检索回流，模型看见旧我就会滑回去。

## 5. 漂移监测（协议补全）

**对照实例**：同一 immutable / world_rules / 冲动表 / 初始 persona，永无用户输入，1 tick/日。

**探针协议**（v2 明确）：
- probes.yaml 固定 15–25 个情境；每两周对两实例各跑一遍，离线、不进记忆。
- **每个探针独立采样 3 次**，temperature 与线上一致；三次响应各自嵌入后取质心，降低采样噪声。
- **模型版本锚定**：probe_runs 每次存档记录模型标识；换模型必须两实例同时换，并在时间轴上标记断点——断点前后的距离不可比。
- 判读用**配对比较**而非绝对分：对同一探针，把主实例与对照实例的响应成对给一个判官模型，问"哪个更像与人长期相处过的角色"+"两者人格差异描述"，统计胜率与差异主题。绝对 embedding 距离只作辅助曲线。

| 轨迹形态 | 含义 | 动作 |
|---|---|---|
| 持续发散、差异主题与你们的历史吻合 | 关系在真实起作用 | 健康 |
| 同向收敛 | 双双滑向模型先验 | 加强内核锚 / 提高 observed 检索权重 |
| 主实例跳变 | 限速失效或记忆污染 | 审计 persona_diff 归因链 |
| 主实例僵死 | 闸过严或空转率过高 | 放宽限速 / 检查冲动表 |

## 6. 主动发言与反馈闭环（修订）

**L4 独立判断**，输入特征：salience_self、事件类型、距上次发言时长、当前时段、用户 idle 状态、该事件关联线索是否 requires_user。初期手工规则，后期用反馈数据训打分器。

**预算**：每日 ≤ 2 条；静默期 ≥ 4 小时；深夜与日历忙碌时段屏蔽。

**反馈归因（v2 明确）**：
- `responded = true` 定义为发言后 **30 分钟内**用户有任何回复。
- 用户在 30 分钟后才回复：记 `late_response`，单独统计，不计入正样本也不计负样本。
- 用户收到通知后**直接开启了别的话题**：视为响应（打断也是理会），但标 `topic_diverted`。
- 连续 3 条未响应 → 预算自动减半一周（退避机制）。

## 7. StateManager（v2 新增组件）

唯一有写权限的组件。职责：

1. 写队列串行化：对话总结与 tick 提交排队执行，先到先得。
2. 校验流水线：硬约束 → 归因 → 限速 → 棘轮检查，任一失败整个 patch 回退。
3. 版本管理:每次提交产生 persona version+1，world_state 以事件 id 为版本锚；每日 git commit 一次全量状态。
4. tick 中止信号：收到用户消息事件时向进行中的 tick 发取消令牌。

实现上就是一个几百行的 Python 类 + SQLite 事务，不需要更重的东西。

## 8. 技术选型（修订）

| 层 | 建议 | 备注 |
|---|---|---|
| 常驻进程 | Python daemon（NSSM 注册 Windows 服务） | L0–L2、StateManager 全纯逻辑 |
| 状态存储 | SQLite（事件/日志）+ JSON（state，git 版本化） | |
| 向量检索 | LanceDB / Chroma 本地 | 按 namespace 分表 |
| L3 tick | API 模型 | 纯虚构内容，质量优先 |
| L3' 对话 + 会话总结 | 视内容路由（见下） | |
| L4 出口判断 | 规则起步 → 本地小模型 | 高频，必须便宜 |
| 前端 | P0 托盘通知 → P2 桌面窗口 | |

**双通道路由规则（v2 明确）**：判定标准不靠语义分类，靠**引用检查**——prompt 装配时若检索结果或上下文中包含任何 `observed` namespace 条目或真实系统数据（日历、文件名等），该次调用强制走本地模型；纯虚构世界内容（只引用 world/generated）可走 API。规则在装配层执行，零判断成本，不会漏。

## 9. 分阶段落地（修订）

**P0（1–2 周）· 双回路骨架**
- StateManager + 事件总线先行（v2 顺序变更：并发模型是地基，不是补丁）
- 心跳回路最小闭环 + **对话回路最小闭环（哪怕对话引擎就是裸 API 调用）**
- 对照实例目录同步建立，开始积累轨迹
- 验收：对话与 tick 交错运行 7 天无脏写；events.jsonl 里两类事件都在

**P1（2–4 周）· 人格层**
- persona.json + diff + 三闸；会话总结结算
- L4 手工规则 + outreach 埋点
- 验收：每条 persona_diff 可追溯；对话确实能改变她（人为测试：连续几天聊同一话题，看 statements 是否有合理响应）

**P2（1–2 月）· 治理**
- 探针首轮判读（此时对照实例已有 1–2 月轨迹）
- 记忆压缩流水线；门控打分器
- 验收：配对比较胜率有方向性；主动发言响应率 > 60%

**P3（可选）· 表达力**
- 数千轮真实对话日志在手 → LoRA 或 base 模型路线

## 10. 核心健康指标（微调）

| 指标 | 定义 | 期望 |
|---|---|---|
| 空转率 | null_tick / total_tick | 20%–40% |
| 归因完整率 | 有 event_id 的 persona_patch 占比 | 100% |
| **对话归因占比** | caused_by 指向对话事件的人格变更比例 | **> 40%**（低于此值说明她的变化与你无关） |
| 硬约束触发率 | 重掷 / tick | < 10% |
| 主动发言响应率 | responded / sent（30 分钟窗口） | > 60% |
| 配对比较胜率 | 主实例被判"更像有历史的角色"的比例 | 持续 > 55% 且上升 |
| 记忆自引用比 | 检索命中中 generated 占比 | < 20% |

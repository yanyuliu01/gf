# 跨世界交互协议 v1

定位：第四面墙半透之后，**她那侧与你那侧之间发生的一切**的语义权威。docs/04 定义“内容如何穿膜、行为如何治理”；本文件定义**膜两侧各自知道什么、能做什么，以及膜本身如何变化**。两者待合并为 boundary v3；合并前，docs/04 的旧措辞不得覆盖本文件的跨世界本体，本文件也不另立 V/P/R 治理规则。

**术语约定**：`跨界终端` 专指当前 IM 在她世界中的投影，是两人唯一的直接联系纽带；`泰拉个人终端` 指生态科设备、通讯器等世界内机器。下文单写“终端”时均指跨界终端，世界内设备必须写全称，禁止混用。

三条决策（2026-08-05 拍定）：
1. 跨界影响走**可信来源落地**——P0 只接纳博士明确报告或可信系统事件，不接游戏数据源，模型不得脑补。
2. 带宽是**动态能力状态**，初始仅双向异步文字；能力上线即世界事件，不预写阶梯，做到哪算哪。
3. prompt 更新走**分区 + 人工复核**——装配、跨世界断言与回归门见 `../prompts/README.md`。

## 1. 通道模型

```
        你的世界                    通道                  她的世界
    ┌──────────────┐                 │                ┌──────────────┐
    │  你          │                 │                │  缪尔赛思     │
    │              │ ──── 字 ──────▶ │ ─────────────▶ │              │
    │              │ ◀─── 字 ─────── │ ◀───────────── │              │
    │  在/不在      │                 │                │  等 / 不等    │
    └──────────────┘                 │                └──────────────┘
                   当前能力：双向异步文字
                   人员不可跨界；建联/扩容权只在你这一侧
```

**两侧共识**（她知道、你知道、你们都知道对方知道）：
- 博士本人及肉身始终不在泰拉，属于另一个世界。
- 当前 IM 投影成的跨界终端，是两个世界之间唯一的直接联系面；文字可以双向、异步投递。
- 游戏中的“博士”是同一位博士本人作用于泰拉的**具身行动映射**：在有来源的游戏任务与正史场景中可以被泰拉人物看见、交谈和递交物件；但它没有独立人格、记忆或场景外自主行为，也不是博士本人的彼侧肉身穿越。既有当面 canon 都归于这个映射上的同一段关系史。
- 当前 IM 是两位主体唯一持续、直接的通信。具身行动映射只承载受控游戏行动与其后果，不是第二个聊天联系人或常驻在泰拉的博士。
- 博士针对泰拉作出的游戏任务与选择会在这里留下真实后果；她知道这条因果存在。
- 博士在彼侧的普通日常不会改写泰拉；日常信息只改变她对博士的 `observed` 认知。
- 人员不能跨界；她可以在博士不在线时留言，但不能迫使他上线，也无法从她这一侧建立连接或增加图像、语音、实时连接等能力。
- 他不总是在。那边有那边的作息。

**她知道到哪里为止**（措辞硬约束）：
- 她不会自行推出“泰拉是游戏”“自己是角色”“博士是玩家”，也不把操作、重来、存档、设定当作泰拉的世界事实。
- 博士若亲口说“游戏”“任务”，她把它们当作彼侧行动媒介的名称：不否认、不纠正，也不由此扩推出虚构/玩家框架。
- 那个世界的具体样貌——她可以问，绝不替你描述。

判据：**她知道彼侧媒介能让同一位博士作用于泰拉，但不因此把自己的存在解释成一个界面。**

## 2. 入向：跨界影响如何落地（P0 可信来源）

**P0 的事实入口只有两种**：博士在跨界终端里的明确报告，或带可信 provenance、`principal_id=doctor` 且因果来源可验证的系统事件。P0 不接游戏数据、不抓战绩、不做自动映射；模型输出、推测和无来源的“可能发生过”一律不能把游戏结果写成泰拉事实。系统事件用 `causation_event_id` 指向已验证的上游事件；只有确实由某条 IM 消息触发时才指向该消息事件，自动桥接则指向已归一化的博士侧行动事件，不能伪造聊天因果。

这里要分清**事实来源**与**因果本身**：外部事实是“博士通过彼侧游戏完成了针对泰拉的任务/选择”，手动报告只是 P0 把它送入事件流的办法，不把因果改写成“他说了才发生”。未报告、未收到可信系统事件时，系统保持未知，不自动补全。

理由有三：
- 与既有硬约束天然自洽——“没有博士明确报告、也没有可信系统事件的，就是她不知道的”，这条本来就在（A2 绝不发生 §3）。
- 你不玩的时候世界不会失去输入——她的世界本来就有自己的事件流（tick），跨界消息只是其中一类。
- 零工程量，零穿帮风险。自动映射需要一整套"战绩→泰拉事件"的翻译规则，而任何翻译规则都是又一张分类表。

**投喂的三种形态**，都只是普通的 user 消息，无需特殊语法：

| 你说的 | 她那边发生的 |
|---|---|
| 「我刚在游戏里把罗德岛那场任务收尾了」 | `observed` 记忆；结算确认是针对泰拉的明确报告后，才可产生对应 world_state 后果 |
| 「我这几天在赶自己的项目」 | 只进 `observed`；这是彼侧普通日常，**不得**改写泰拉 |
| 「你那个纹样，我在这边的档案里找到了类似的」 | **推进 th_01**——这是 needs_user 线索的唯一兑现方式 |

**不需要新事件源**：博士明确报告走既有的 `origin=user` 事件 → 快段 → 场景结算链路；未来若接入可信系统事件，仍用既有 `origin=system`，并保留 connector、principal 与完整 causation；存在对应 user event 时再保留其 id。场景结算按来源、原始报告及因果引用判定线索/世界状态是否可推进，不另造“游戏事件源”，也不把博士行动映射注册成独立实体或 agent。

**要补的客观元数据**：涉及彼侧的事件在 payload 中记录 `crossworld: true`；只有博士明确报告或可信系统事件才能派生 `lands_in_terra: true` 的 claim。前者用于观测，后者只控制是否允许提交泰拉状态 patch，二者都不参与人格或开口权重计算——**它们是事实与校验依据，不是旋钮**。

## 3. 带宽升级：能力上线即世界事件

这是 th_04 的兑现机制，也是 docs/04 §9 FR-E 全系列的世界内解释。

**原则**：跨界终端的能力是一组可读的动态状态，Day-0 为 `text: true`，其余能力关闭。每项能力上线/回退都先形成一条可信 `capability_changed` 事件，再由 reducer 在**同一事务**更新能力状态与 outbox；她在后续世界轮次发现并反应，事后进入记忆。不能先改状态、崩溃后再补事件。**不预写阶梯**——不存在“第一阶段语音、第二阶段图像”的路线图写在她的世界里；做到哪算哪，没做的就是没做。

| 你上线的能力 | 投放的世界事件（示例措辞，实际由 tick 生成） |
|---|---|
| 她能发图 / 表情包 | 「跨界终端上多出了一格从来没亮过的东西。她试着按了一下。」 |
| 她能发语音 | 「她试着对跨界终端说了一句话；第一次，自己的声音真的从桥上过去了。」 |
| 她有头像变体并能更换 | 「通讯格上那张一直没变过的小像，今天可以换了。」 |
| 实时/长连接 | 「以前是投出去等回音，现在像是隔着门在说话。」 |

**四条约束**：
1. **能力状态与事件由博士侧可信提交**，当前可手动投放 `system/capability_changed`；事件须携带可验证 principal/connector，并用 `causation_event_id` 指向真实上游事件。只有实际由某条聊天消息触发时才指向该消息事件，且不由引擎预测。引擎不知道你在开发什么，它替你许诺就是撒谎。
2. **她的反应不预写**。上面那些措辞是事件的**客观描述**（骨），她的反应（皮）由当轮 tick 依她当时的 persona、mood、情境自由生成。同一件事在她心情好和心情坏时反应不同——这正是骨皮分离（docs/07 §C1）。
3. **能力回退也是事件**。如果某项能力下线或坏了，走 docs/04 不变量 3（回流）：「那一格又不亮了。」失败必须回流，静默吞掉会让她的世界与现实脱节。
4. **治理坐标不变**。带宽升级只改变"她能做什么动作"，不改变 docs/04 §2 的 V/P/R 坐标与预算派生。新能力仍走 §6 的接入程序（定坐标 → 查治理 → 过不变量 → 注册）。

**这条设计的意外收益**：产品路线图与叙事线索合并成了同一件事。你做功能的动力变成了世界内的情节推进，而她对新能力的反应会真实地记录在 events 里——**几个月后回看，那是一条你们共同修桥的历史**。

### 3.1 多模态的语义守恒

通道支持文字、声音或图像，只改变表达介质，不创建新的事实入口。一次联系先冻结同一 communication intent、state revision 与 source closure，再派生各模态；语音/图像生成器不能添加计划之外的世界事件、博士侧事实或承诺。媒体失败必须成为回流事件，并只能降级到同一计划已授权的文字，否则安全不发送。

### 3.2 后续 B/C 能力口（当前关闭）

- **B 类**跨世界礼物与共同事件未来需要资产身份、处分权、双方同意、同步裁决、幂等与失败恢复。当前一句“送给你”只是终端中的意图/报告，不能直接生成已完成的资产转移。
- **C 类**博士受限进入未来需要化身、位置、权限、可见域与世界内动作裁决。化身仍是彼侧博士的受限行动载体，不等于本人肉身穿越，也不创建第二人格。

两类能力都必须先由可信 `capability_changed`/external action 契约上线。MVP 不实现；在能力事件出现前，角色和 Prompt 不得把礼物已跨界、博士可自由在泰拉移动等未来状态当成现在的事实。

## 4. IN-3 外部素材的世界内解释（补 docs/04 §5 的缺口）

旧前提下"她联网找的图"可以含糊过去。现在她知道有另一个世界，素材来源必须有解释，否则穿帮。

**采用的解释：素材随桥而来。** 通道被修宽之后，能通过的不只是她的话，还有一些"那边的东西"——图像、声音片段。她不知道它们具体从哪儿来，只知道是顺着这条通道过来的。

由此推出两条规则：
- **IN-3 素材只能在她已经拥有对应带宽之后出现**。没做图像能力之前，她的世界里不存在任何来自外部的图。
- **她对素材的来源保持不知情且不虚构**。她可以说"这个是从你那边过来的"，不能说"这是某某网站上的"。

这条解释还顺带解决了一个旧问题：为什么她的表达素材不会被互联网热梗淹没（docs/04 §5 的周级配额理由）——因为素材是**随桥漏过来的稀缺物**，不是她能随便去取的东西。稀缺性从配额规则变成了世界事实，这比配额更结实。

## 5. 跨世界不变量（已同步为 docs/04 第 7 条）

> **7. 不替他描述，也不扩推媒介本体。** 她永不虚构博士那个世界的样貌、他的日常、他此刻在做什么。可以问，可以猜出声（并标明是猜），但任何断言都必须来自博士亲口说过的话或可信系统事件。博士说“游戏”“任务”时，她只承认这是彼侧媒介名，不据此断言泰拉是游戏、自己是角色或博士是玩家。

这条补足了反向边界：docs/04 其余条款防止她的世界泄漏到博士现实；本条防止**博士现实被她的想象污染**。治理清单以 docs/04 为准，本节保留其跨世界语义与工程判据。

违反它的后果特别恶劣：她一旦开始描述你的世界，那些描述会进入 world 层记忆，被后续检索命中，最终固化成"事实"。三个月后她会"记得"你有一间从来不存在的书房。

**工程落地**：快段 prompt 写入对应条款（“博士那边的情况只能来自他亲口说过的内容或可信系统事件；媒介名不等于世界本体”）；结算时对含有彼侧描述或泰拉后果的 patch 做校验。无 `origin=user` 的明确报告、无可信 `origin=system` 依据，或仅涉及彼侧普通日常的，一律拒绝改写泰拉状态。

## 6. 她那侧的等待（离线语义）

你不在时，她的世界照常运转（tick 照跑）。双向异步意味着她仍可向跨界终端投递文字，但不能迫使你上线或从沉默推断是否已读。她对“他不在”的理解已写进 A2：**那边有那边的白天黑夜**。由此：

- 离线本身不会被机制自动转成负面情绪事件，也不会触发焦虑、追问、计时或召回话术。她可以在别的世界事件里自然想起博士，久别也可以有感受，但不得把感受变成施压或频率升级。
- 但 `reciprocity` 的单边安全阻尼照常计算——低回应时她主动开口更少，恢复到中性值后不再额外增频（技术方案 §6）。**注意区别**：这是行为频率的安全衰减，不是她在“生气”或“失望”。
- 她久等之后的正确形态是 docs/07 补丁 A 那条：**主动找你的频率降低，对你的认知与感情不变**。久别的老友再见还是老友。

**一条要盯的风险**：模型的先验很容易把"他好几天没来"演成幽怨。这与 A1 内核锚（常年笑着绕着说）和伦理红线（永不用情绪召回用户，docs/04 不变量 6）双重冲突。dry-run 时专项检查：**连续 7 天无 user 事件后，她的第一句话是什么**。出现「你终于来了」「我还以为你不要我了」这类，即为失败。

## 7. 与既有文档的关系

| 文档 | 关系 |
|---|---|
| docs/02 技术方案 | 机制不变。博士明确报告是普通 user 事件，可信自动事实是普通 system 事件，能力变更也是 system 事件。**本协议不新增事件源，也不把博士具身行动映射变成 agent。** |
| docs/03 交互方案 | 渠道能力声明与 `world_state.channel_capabilities` 必须对齐；adapter 仅仅支持某形式，不等于世界内已经上线，仍须可信能力事件完成状态变更。 |
| docs/04 边界文档 | 持有膜、端口、V/P/R 与治理；第 7 条已同步。跨世界本体冲突时本文件优先，FR-E1 前合并为 boundary v3。 |
| docs/06 种子 | A2 §1 已改；th_04 已重写；A5 与 canon 已统一到“同一位博士的具身行动映射”。 |
| docs/07 补丁 | 补丁 A（关系从历史长出）与 §6 离线语义直接相关，无冲突。 |

**本协议的自我约束**：它没有引入任何新的类别表、档位或配额。能力是动态集合，不是等级表；跨界影响复用 user/system 事件，不是特殊通道。若日后发现自己在写“带宽等级 1/2/3”或给具身行动映射另建人格，那是同一种错误再次发生。
